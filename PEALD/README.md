# PEALD 공정 제어

PEALD 장비의 제어·감시 프로그램입니다. LS XGB PLC 와 **Modbus TCP** 로 통신하며,
PLC 가 서버, 이 프로그램이 클라이언트입니다.

- 백엔드: Python + FastAPI (상태·명령·PLC 링크)
- 화면: pywebview 창 안의 HTML/CSS/JS (**외부 라이브러리 없음**, 오프라인 전제)
- 화면 통신: WebSocket 하나 (`/ws`) — 상태의 주인은 서버입니다

> **버전 0.3.0 (2단계)** — 수동 조작 · 레시피(편집·검증·PLC 표·올리기·시작·진행) ·
> 시뮬레이터 공정 실행 · 공정 데이터 로그까지.
> 설정 편집 화면, 트렌드 이력 저장, 배포용 빌드는 3단계입니다.

```bash
pip install -r requirements.txt
python run.py                 # exe 옆 / 이 폴더의 config.json
python run.py --config 경로
python run.py --headless      # 창 없이 서버만 (검증용)

pip install -r requirements-dev.txt
python -m pytest -q           # 이 폴더에서만 실행
```

★ 이 프로그램은 **POWDERALD 와 완전히 독립**입니다. 서로 import 하지 않고, 포트·뮤텍스·
데이터 폴더도 전부 따로 씁니다. 공통 기반 코드는 양쪽에 복사되어 있습니다(의도된 중복).

## 설정 (`config/config.example.json` → 실제는 exe 옆 `config.json`)

★ **모르는 값은 지어내지 않습니다.** 예시값 + `confirmed: false` 로 두고, 화면에서 그 값 옆에
**"환산 미확정"** 을 붙입니다. 현장에서 확인한 뒤 설정만 고치면 됩니다.

★ 검증은 **기동을 막지 않습니다.** 문제가 있어도 화면은 뜨고, 화면 로그와 파일 로그로 알립니다.

| 항목 | 설명 |
|---|---|
| `server` | `host`(기본 127.0.0.1), `port`(8201) |
| `window.side` | `left` / `right` — 작업 영역(작업표시줄 제외)의 정확히 절반 |
| `plc.host` `.port` `.unit_id` | 실장비 주소 (예시는 `192.168.10.x`) |
| `plc.timeout_ms` `.poll_ms` `.heartbeat_ms` | 응답 제한 1000 · 상태 읽기 100 · 하트비트 500 |
| `plc.simulate` `.sim_port` `.sim_speed` | 내장 시뮬레이터 사용 여부 · 포트(15201) · 시간 배속(기본 5) |
| `analog.raw_max` | 아날로그 원시값 최대 (예시 16000, **확정 전**) |
| `pressure.cvg` | CVG 환산 — `loglinear` / `linear` / `table` |
| `pressure.cm` | 커패시턴스 게이지 (`installed: false` 면 표시하지 않음) |
| `mfc[]` | `no`, `name`, `gas`, `full_scale_sccm`(null = 미정), `confirmed` |
| `heaters[]` | `ch`, `name`, `enabled`, `max_c`(null = 미정), `default_sv` — 12채널 |
| `rf` | `max_w` — 원시값 최대에 해당하는 W |
| `pcv` | `full_pct` — 개도 % 환산 |
| `params` | 아래 PLC 파라미터 (공학 단위로 적고, 프로그램이 원시값으로 바꿔 씁니다) |
| `log` | `level`, `keep_days` |
| `access.local_only` | 조작은 이 PC 에서만 (원격은 보기 전용) |

### 환산은 반드시 단조 증가여야 합니다

원시값이 커지면 공학값도 커져야 합니다. 베이스 압력 같은 설정을 PLC 에 넣을 때
**역함수**를 쓰기 때문입니다. 단조가 깨지면 역함수가 여러 답을 갖고, PLC 에 엉뚱한
기준값이 들어갑니다. `config.py` 가 기동할 때 이것을 검사합니다.

CVG 기본형(`loglinear`):

```
V = raw / raw_max × volt_max
p = torr_at_0v × 10 ^ (V × decades_per_volt)
```

### 히터 과온 한계가 `null` 이면

PLC 한계(`D01110~21`)에 **0** 을 씁니다. PLC 는 한계가 0 인 채널을 막으므로 그 히터는
올라가지 않습니다. 화면은 표에 **"한계 미정"** 경고를 띄웁니다.

## PLC 통신 약속

### 기본

- Modbus TCP, PLC 가 서버. **홀딩 레지스터 번호 = D 번호** (D01001 → 1001)
- FC03 읽기(한 번에 최대 125), FC06 한 개 쓰기, FC16 여러 개 쓰기(120 개씩 나눔)
- 값은 **부호 없는 16비트**로 주고받고, 부호 있는 값(히터 온도 ×0.1 ℃)만 해석할 때 바꿉니다
- DWORD 는 **아래 주소가 하위 워드** (D00024 하위, D00025 상위)
- 트랜잭션 번호를 확인하고, 시간 초과가 나면 소켓을 버립니다 —
  늦게 도착한 응답을 다음 요청의 응답으로 읽으면 엉뚱한 주소의 값을 믿게 됩니다
- 요청은 한 번에 하나(잠금). 끊기면 1 → 2 → 5 s 간격으로 다시 붙습니다

### 주기 (백그라운드 태스크 하나가 소켓을 가집니다)

| 주기 | 하는 일 |
|---|---|
| 100 ms | 상태 영역 `D00000~D00080`(81 워드)을 한 번에 읽기 |
| 500 ms | `D01000`(PC 하트비트)에 +1 쓰기 |
| 500 ms | 표시용 내부 영역 `D04120~D04131` 읽기 (실제로 출력 중인 설정값) |

★ **PC 하트비트는 화면·명령 처리와 무관하게 계속 돌아야 합니다.** PLC 는 이 값이
`PRM_PC_WDT_MS`(기본 3000 ms) 동안 안 바뀌면 PC 끊김으로 보고 안전 정지합니다.

PLC 하트비트(`D00000`)가 2 s 넘게 안 바뀌면 **"PLC 하트비트 멈춤"** 으로 봅니다
(통신은 되는데 PLC 가 STOP 인 경우).

### 연결할 때마다 (처음 · 재연결)

1. `D01000~D01042` 를 읽어 PC 의 수동 요청 값을 PLC 에 남아 있는 값으로 맞춥니다
2. 다음 명령 번호 = 읽은 `D01001` + 1 (0부터 다시 시작하면 PLC 가 무시합니다)
3. `params` 를 원시값으로 바꿔 PRM 영역에 쓰고 **되읽어 확인**합니다(다르면 경고)

PLC 는 첫 스캔에 0 인 PRM 만 기본값을 넣습니다
(WDT 3000 · PUMP_TO 600 · VENT_TO 300 · MFC_STABLE 3 · MFC_TO 60 · VLV_MIN 200).
베이스 압력·허용 편차·히터 한계·RF 상한은 **0 이면 해당 기능을 막거나 끄므로** PC 가 매번 씁니다.

### 명령 핸드셰이크 (한 번에 하나)

```
① 인자 레지스터(수동 밸브·보조·MFC·히터·SP)가 있으면 먼저 쓴다
② D01002 명령 코드
③ D01001 명령 번호 (이전 +1, 65535 다음 0)   ← 번호를 마지막에 써야 PLC 가 완성된 명령을 본다
④ D00002 가 그 번호가 될 때까지 최대 1.5 s 기다려 D00003 결과를 읽는다
```

★ 시간 초과면 **"PLC 응답 없음"** 으로 끝내고 **같은 명령을 자동으로 다시 보내지 않습니다** —
PLC 가 이미 받았을 수 있어 두 번 실행될 위험이 있습니다.

**결과(`D00003`)**: `0` 처리됨 / `1` 인터락 조건 미달(무엇이 빠졌는지 비트를 풀어서 알려 줍니다)
/ `2` 지금 상태에서 할 수 없음 / `3` 레시피 표 오류 / `4` PLC 가 모르는 명령

**명령 코드(`D01002`)**

| | | | |
|---|---|---|---|
| 1 공정 시작 | 2 일시정지 | 3 재개 | 4 사이클 끝나면 정지 |
| 5 즉시 중단 | 6 알람 확인(부저 끔) | 7 알람 리셋 | 8 펌핑 시작 |
| 9 펌핑 정지 | 10 벤트 | 11 전체 밸브 닫기 | 12 수동 적용 |
| 13 히터 적용 | 14 MFC 수동 적용 | | |

**PLC 가 거절하는 규칙**

- 공정 중이면 9~14 → `2`
- 8 은 비상정지·펌프·공압·냉각수 알람 중 → `1`
- 12 는 안전 정지 요구 중 → `1`
- 2 는 공정 중이 아니거나 이미 일시정지면 → `2`
- 3 은 일시정지가 아니면 `2`, 안전 정지 요구 중이면 `1`
- 1 은 공정 중이면 `2`, 공정 시작 허가가 없으면 `1`, 레시피 표 불합격이면 `3`

PC 도 같은 규칙으로 버튼을 미리 잠그고 이유를 보여 주지만(편의) **최종 판단은 PLC 결과**입니다.
서버는 원격 접속의 조작 명령과 PLC 연결 끊김 중 명령을 거절합니다.
모든 명령은 (시각·명령·번호·결과·보낸 곳)이 프로그램 로그에 남습니다.

### 비트 정의

**공정 밸브** (`D00010` / `D01004` / 레시피 밸브 워드) — 수동 반영 마스크 `0x01FF`

| b0 | b1 | b2 | b3 | b4 | b5 | b6 | b7 | b8 |
|---|---|---|---|---|---|---|---|---|
| PV-1 캐니스터1→전구체 라인 | PV-2 캐니스터2→ | PV-3 캐니스터3→ | PV-A1 어시스트→캐니스터2 | PV-A2 어시스트→캐니스터3 | PV-R 매니폴드→챔버 | PV-R1 퍼지 N2→매니폴드 | PV-R2 H2O 캐니스터→ | PV-R3 O2→ |

**보조 출력** (`D00014` / `D01008`) — 명령 12 반영 마스크 `0x0F00`

b0 VV 챔버 벤트 · b1 IV-E 배기 격리 · b2 펌프 N2 퍼지 · b3 드라이펌프 기동 ·
b4~b6 경광등 적/황/녹 · b7 부저 · **b8 RF ON**
(VV·IV-E·펌프는 명령 8~11 이 다룹니다)

**입력 워드0** (`D00008`)

b0 비상정지 정상(B접) · b1 판넬 리셋 스위치 · b2 공압 · b3 N2 · b4 냉각수 ·
b5 리드 닫힘 · b6 챔버 대기압 · b7 펌프 운전 · b8 펌프 알람 ·

## 내장 PLC 시뮬레이터

`plc.simulate` 가 `true` 면 프로그램 안에서 `127.0.0.1:sim_port` 에 Modbus TCP 서버를 띄우고,
PLC 링크는 그 주소에 붙습니다. **실장비와 똑같은 통신 코드를 탑니다** — 시뮬레이터용 지름길을
만들지 않았기 때문에, 여기서 통과한 것이 현장에서도 통과합니다.

20 ms 주기로 주소표 사양을 흉내 냅니다. 물리값(압력·온도 곡선)은 대략이지만
**상태 코드·결과 코드·비트 의미는 정확합니다.** 헤더에 **시뮬레이터** 칩이 항상 뜹니다.

칩을 누르면 **조작판**이 열립니다(이 PC 접속에서만). 이상 입력을 켜서 알람·인터락 동작을
확인할 수 있습니다 — 비상정지, 공압, N2, 냉각수, 리드 열림, 펌프 알람, 가스 누출, 히터 과온,
RF 준비 끔 / RF 알람 / 반사 전력 증가, 그리고 **PC 하트비트 멈춤(시험)**.

## 레시피

레시피는 `data/recipes/<이름>.json` 한 파일입니다. 다른 장비 형식(`format`)의 파일은
목록에도 올리지 않습니다 — 밸브 이름이 같아 보여도 배관이 달라 그대로 실행하면
엉뚱한 곳을 엽니다.

```jsonc
{
  "format": "PEALD-recipe/1",
  "name": "예시", "memo": "", "created": "...", "modified": "...",
  "blocks": [{
    "name": "블록 1",
    "repeat": 100,                      // 이 블록을 몇 사이클 돌릴지
    "mfc_sccm": [0, 0, 0, 0],        // MFC1 · MFC2 · MFC3 · MFC4
    "pcv_pct": 50, "rf_w": 200,
    "steps": [
      { "name": "전구체", "time_ms": 100, "valves": ["PV-1"], "pause_ok": false, "rf": false },
      { "name": "퍼지",   "time_ms": 3000, "valves": [],       "pause_ok": true, "rf": true }
    ]
  }],
  "groups": [ { "from": 1, "to": 2, "repeat": 10 } ]   // 블록 묶음 반복 (겹칠 수 없음)
}
```

한계: 스텝 100 · 블록 10 · 그룹 5 · 스텝 시간 20~3,276,700 ms ·
블록 반복 1~1,000,000 · 그룹 반복 1~65,535.

### 검증 (서버에서만 합니다)

화면은 편집한 내용을 `recipe_validate` 로 보내고 **오류·경고·예상 시간을 받아 그리기만**
합니다. 화면이 따로 계산하면 두 값이 달라지고, 운전자는 어느 쪽을 믿어야 할지 모릅니다.

오류(올릴 수 없음)와 경고(올릴 수 있지만 확인이 필요함)를 구분합니다.

- 오류 — 한계 초과, 스텝·블록이 없음, 이름이 비었거나 너무 김, 시간이 범위 밖,
  모르는 밸브 태그, 전구체와 반응물을 한 스텝에서 함께 여는 것, 그룹 범위가 잘못됐거나
  서로 겹치는 것, 설정값이 범위 밖(MFC 풀스케일·RF·PCV 상한·PLC 가 막는 0),
  풀스케일·상한이 **미정**인데 0 이 아닌 값을 쓴 것(원시값으로 바꿀 수 없습니다)
- 경고 — 새로 열리는 밸브가 있는 스텝이 `valve_min_ms` 보다 짧아 **PLC 가 늘리는 것**,
  60 s 를 넘는 스텝(PLC 가 100 ms 단위로 내림), 퍼지 스텝이 없는 것,
  보조 밸브만 열고 짝이 되는 밸브를 안 연 것, RF 스텝이 있는데 블록 RF 전력이 0 인 것

### 시간 계산

스텝 실제 시간 = 새로 열리는 밸브가 있으면 `max(설정, valve_min_ms)`,
60 s 를 넘으면 100 ms 단위로 내림. 블록 시간 = 준비 시간(MFC 안정 `mfc_stable_s`) +
1회차 사이클 + (반복-1) × 이후 사이클. 전체 = 블록 합 + 그룹 반복분.
**진행 화면의 남은 시간도 같은 함수로 계산합니다** — 두 값이 어긋나면 안 됩니다.

### PLC 표로 바꾸기 · 올리기

레시피 → `D02000~D03119`(1120 워드).

| 영역 | 내용 |
|---|---|
| D02000~04 | 스텝 개수 · 블록 개수 · 그룹 개수 · 합계 · 레시피 번호 |
| D02100~ | 스텝 n: 8 워드 (밸브 비트 32 · 시간 ms 32 · 플래그) |
| D02900~ | 블록 n: 16 워드 (시작 스텝 · 스텝 수 · 반복 32 · 설정값) |
| D03100~ | 그룹 n: 4 워드 (시작 블록 · 끝 블록 · 반복) |

- 합계 = `D02000~D03119` 중 `D02003` 을 뺀 모든 워드의 합의 하위 16비트
- 레시피 번호 = 레시피 내용(메모·시각 제외)의 CRC32 하위 16비트(0 이면 1) —
  **데이터 로그와 PLC 가 들고 있는 것을 대조**하는 데 씁니다
- 올리는 순서: **본문 먼저, 헤더(개수·합계)를 마지막**. PLC 는 1 s 마다 헤더를 보고
  표를 검사하므로, 헤더를 먼저 쓰면 아직 안 올라온 본문으로 검사해 불합격이 뜹니다
- 올린 뒤 **되읽어 워드 단위로 비교**하고, PLC 의 검사 결과(`D00029`)를 3 s 까지 기다립니다
- 보낸 합계와 PLC 가 계산한 합계가 다르면 **실패로 보고**합니다 —
  표는 이미 올라갔을 수 있으므로 "올라갔다"고 말하지 않습니다
- 공정 중에는 올리지 않습니다. PLC 는 시작할 때 작업본(`D05000~`)으로 복사해 돌기 때문에
  실제 영향은 없지만, 화면과 실제가 달라 보이기 때문입니다

## 공정 시작 흐름

시작은 명령 하나가 아니라 흐름입니다.

```
레시피 검증 → PLC 표 올리기 → 베이스 압력 대기 → 명령 1(공정 시작)
```

- 시작 조건은 **서버가 판정**하고 화면은 항목과 현재 값을 받아 그립니다:
  PLC 연결·하트비트 / 장비 상태 / 중대 알람 없음 / 펌프 / 공정 밸브 허가 /
  베이스 압력 / 레시피 검증 / (설정으로 켜면) 히터 안정
- **베이스 압력만은 시작을 막지 않습니다** — 기다리면 채워지는 조건이라 대기로 처리합니다
- 대기 중 PLC 가 끊기거나 안전 정지 요구·중대 알람이 생기면 대기를 접습니다.
  운전자가 [대기 취소]로 멈출 수도 있습니다
- 최종 판단은 PLC 결과입니다. 결과 1(인터락)이면 **빠진 조건을 풀어서** 알려 줍니다
- PC 를 다시 켰을 때 PLC 가 이미 공정 중이면, PLC 레시피 번호로 로컬 레시피를 찾아
  이어서 표시합니다(못 찾으면 번호만 표시합니다)

운전 중 조작: 일시정지 / 재개 / 사이클 후 정지 / 즉시 중단.
일시정지는 `pause_ok` 스텝에서만 실제로 멈춥니다(PLC 가 판단합니다).

## 수동 조작

- **밸브** — 잠금 해제(5분)를 켜야 누를 수 있고, 공정이 시작되면 서버가 다시 잠급니다.
  요청과 실제 반영을 나란히 보여 줍니다(요청했는데 안 열린 것은 `대기`).
  전구체와 반응물을 함께 여는 요청은 PC 가 먼저 막습니다 —
  PLC 도 둘 다 막고 중대 알람을 냅니다
- **명령 12(수동 반영)는 한꺼번에 반영**되므로, 누를 때마다 **수동 요청 전체**를 씁니다.
  빠뜨린 값은 0 으로 반영되어 먼저 연 밸브가 닫힙니다
- PLC 가 스스로 지운 요청(전체 닫기·공정 시작·안전 정지·대기압)은 **요청 레지스터를
  되읽어** 확인하고 PC 요청도 0 으로 맞춥니다. 실제 출력으로 판단하면 허가를 기다리는
  요청까지 지워집니다
- **MFC** — 풀스케일이 미정이면 거절합니다(원시값을 만들 수 없습니다)
- **히터** — 설정 온도·전원. 과온 한계가 미정인 채널은 PLC 가 막습니다. 공정 중에는 못 바꿉니다
- **PCV** — 0~100 %.
- **RF 시험** — 대기 중에만. 전력이 0 이면 PLC 가 RF 요청을 지우므로 PC 가 먼저 막고,
  켤 때는 확인 창을 거칩니다. 압력·반사 전력 조건은 PLC 가 계속 봅니다

## 화면 ↔ 서버 통신 약속

WebSocket 하나(`ws://<host>:<port>/ws`)로 주고받습니다. 트렌드 이력만 HTTP 입니다.

★ **상태의 주인은 서버입니다.** 화면은 값을 지어내지 않습니다.
PLC 가 끊기면 모든 값이 `null`(화면에서 `—`)이고 명령 버튼이 잠깁니다.
**값 없음과 0 을 반드시 구분합니다** — 끊긴 채로 0 을 보여 주면 "유량이 0"으로 오해합니다.

### 서버 → 화면

| type | 언제 | 내용 |
|---|---|---|
| `state` | 접속 직후 · 구조가 바뀔 때 | `device` `structure` `config` `unconfirmed` `notices` `alarm_history` `logs` `sim_faults` `access` `live` |
| `live` | 5 Hz | 아래 |
| `log` | 로그 한 줄 | `level` `msg` `ts` |
| `notice` | 토스트 | `level` `msg` |

`state.device` — `name` `title` `theme` `accent` `plc_addr` `simulate` `has_rf` `has_o3` `has_pcv`
(장비 정체성. 설정이 아니라 `device.py` 에서 옵니다)

`state.structure` — `valves` `aux` `inputs0` `inputs1` `interlocks` `mfc` `heaters`
`state_names` `seq_names` (화면은 비트 번호나 D 주소를 모릅니다. 전부 여기서 이름을 받습니다)

그 번호에 맞는 로컬 레시피 이름). 5 s 마다 되읽습니다 — 편집 중인 것과 장비가 들고 있는 것을

| 레시피 | `recipe_validate` `recipe_load` `recipe_save` `recipe_rename` `recipe_delete` `recipe_select` `recipe_upload` `plc_recipe_read` |
| 공정 | `process_start` `process_cancel_wait` `process_pause` `process_resume` `process_stop_after_cycle` `process_abort` |
| 수동 | `manual_unlock` `manual_valve` `manual_mfc` `manual_heater` `manual_pcv` `manual_rf` |
| 그 밖 | `sim_fault`(시뮬레이터 조작판) `alarm_popup_close` `exit` |

`recipe_validate` 의 답은 `recipe_check`(오류·경고·요약), `recipe_load` 의 답은 `recipe`
입니다. 둘 다 **보낸 화면에만** 돌려줍니다.

**원격(루프백이 아닌 접속)의 조작 명령은 전부 거절합니다.** 주소를 판정할 수 없으면
원격으로 봅니다(안전한 쪽으로 틀립니다). 거절할 때는 항상 `notice` 로 이유를 돌려줍니다.

## 화면에서 지키는 것

- 색·간격·글꼴은 `css/tokens.css` 의 CSS 변수만 씁니다. 컴포넌트 CSS 와 JS 에 hex 를 쓰지 않습니다.
- 장비 고유색(`--accent`)은 **헤더 띠 · 장비 배지 · 선택된 탭 밑줄 · 확인 창**에만 씁니다 —
  상태색(정상 초록 · 경고 주황 · 알람 빨강 · 꺼짐 회색)과 겹치지 않게.
- 위험하거나 되돌리기 어려운 명령은 **확인 창**을 띄우고, 제목에 장비 이름을 고유색으로 크게
  씁니다 — 두 창이 나란히 떠 있을 때 다른 장비에 명령을 보내는 사고를 막는 마지막 방어선입니다.
- 숫자 포맷은 `js/fmt.js` 한 곳에서만 합니다. 압력은 0.1 Torr 미만이면 지수표기입니다.
- 뷰 모듈은 전부 `render(state)` / `update(live)` 두 함수 형태입니다.
- 서버·PLC 에서 온 문자열은 `textContent` 로 넣거나 이스케이프합니다.
- 오프라인 전제 — 웹폰트·CDN·외부 네트워크 요청이 하나도 없습니다.
