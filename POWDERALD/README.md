# Powder ALD 공정 제어

Powder ALD 장비의 제어·감시 프로그램입니다. LS XGB PLC 와 **Modbus TCP** 로 통신하며,
PLC 가 서버, 이 프로그램이 클라이언트입니다.

- 백엔드: Python + FastAPI (상태·명령·PLC 링크)
- 화면: pywebview 창 안의 HTML/CSS/JS (**외부 라이브러리 없음**, 오프라인 전제)
- 화면 통신: WebSocket 하나 (`/ws`) — 상태의 주인은 서버입니다

## 설정 (`config/config.example.json` → 실제는 exe 옆 `config.json`)

★ **모르는 값은 지어내지 않습니다.** 예시값 + `confirmed: false` 로 두고, 화면에서 그 값 옆에
**"환산 미확정"** 을 붙입니다. 현장에서 확인한 뒤 설정만 고치면 됩니다.

★ 검증은 **기동을 막지 않습니다.** 문제가 있어도 화면은 뜨고, 화면 로그와 파일 로그로 알립니다.

| 항목 | 설명 |
|---|---|
| `server` | `host`(기본 127.0.0.1), `port`(8101) |
| `window.side` | `left` / `right` — 작업 영역(작업표시줄 제외)의 정확히 절반 |
| `plc.require_device_id` | **장비 ID 필수** (기본 `false`). 켜면 ID 0 인 PLC 도 '이 장비 PLC 인지 확인 못 함'으로 보고 모든 쓰기를 막습니다 — 두 PLC 에 ID 렁을 넣은 뒤 켭니다. 다시 시작해야 반영 |
| `plc.host` `.port` `.unit_id` | 실장비 주소 (예시는 `192.168.10.x`). ★ **코드 기본값이 없습니다** — 시뮬레이터가 아닌데 비어 있으면 연결하지 않고 오류로 알립니다 |
| `plc.timeout_ms` `.poll_ms` `.heartbeat_ms` | 응답 제한 1000 · 상태 읽기 100 · 하트비트 250 |
| `plc.simulate` `.sim_port` `.sim_speed` | 내장 시뮬레이터 사용 여부 · 포트(15101) · 시간 배속(기본 5) |
| `analog.raw_max` | 아날로그 원시값 최대 (예시 16000, **확정 전**) |
| `pressure.cvg` | CVG 환산 — `loglinear` / `linear` / `table` |
| `pressure.cm` | 커패시턴스 게이지 (`installed: false` 면 표시하지 않음) |
| `mfc[]` | `no`, `name`, `gas`, `full_scale_sccm`(null = 미정), `confirmed` |
| `heaters[]` | `ch`, `name`, `enabled`, `max_c`(null = 미정), `default_sv` — 12채널 |
| `o3` | `unit`, `full` — 원시값 최대에 해당하는 농도 |
| `params` | 아래 PLC 파라미터 (공학 단위로 적고, 프로그램이 원시값으로 바꿔 씁니다) |
| `log` | `level`, `keep_days` |
| `process.press_high_*` · `heater_dev_*` | v0.7.0 공정 중 압력 상한 · 히터 이탈 경고 — **PC 감시**(프로그램이 꺼져 있으면 동작하지 않음). 0 = 끔 |
| `leakcheck` | v0.7.0 누설률 점검 — `settle_s` 10 · `measure_s` 120 · `limit_mtorr_min` 10 · `max_torr` 1.0 |
| `maintenance` | v0.7.0 정비 카운터 한계 — `valve_opens_warn` · `pump_hours_warn` · `o3_hours_warn`(0 = 끔) |
| `access.local_only` | 조작은 이 PC 에서만 (원격은 보기 전용) |

### 환산은 반드시 단조 증가여야 합니다

원시값이 커지면 공학값도 커져야 합니다. 베이스 압력 같은 설정을 PLC 에 넣을 때
**역함수**를 쓰기 때문입니다. 단조가 깨지면 역함수가 여러 답을 갖고, PLC 에 엉뚱한
기준값이 들어갑니다. `config.py` 가 기동할 때 이것을 검사합니다.

CVG 기본형(`loglinear`):

```
V = raw / raw_max × volt_max
p = torr_at_0v × 10 ^ (V × decades_per_volt)
```

### 히터 과온 한계가 `null` 이면

PLC 한계(`D01110~21`)에 **0** 을 씁니다. PLC 는 한계가 0 인 채널의 **소프트 과온 감시만
하지 않을 뿐 전원을 막지 않습니다**(과온 스위치 입력은 그대로 봅니다). 감시 없는 히터가
켜지지 않도록 **PC 가 그 채널의 목표 온도·전원 켜기를 모두 거절**하고, 화면은 표에
**"한계 미정"** 경고를 띄웁니다.

`heaters[].station` 은 그 채널이 붙은 온도조절기 국번(1~3)입니다. 없으면 4채널씩 묶은
기본 배선(`(ch-1)//4+1`)으로 봅니다. 통신 끊김(`D00054`) 판정에 씁니다.

### ★ 온도조절기 통신이 없는 채널은 켤 수 없습니다

PLC 과온 감시(P35 — 현재값 > `PRM_HTR_MAX`)는 **온도조절기 통신으로 읽은 현재값(`D00030~`)이
있어야** 동작합니다(래더의 온도조절기 통신 P20 이 들어가기 전에는 모든 국번이 통신 없음입니다).
그 채널은 하드웨어 과온 스위치 말고 보호가 없으므로:

- 그 국번의 `D00054` 비트가 0 이면 **전원 켜기를 거절**합니다 —
  "온도조절기 통신이 없어 PLC 과온 감시가 동작하지 않습니다 — 전원을 켤 수 없습니다"
- 설정 온도 변경은 거절하지 않되 **'온도조절기에 전달 안 됨'** 경고를 붙입니다
- 운전 화면 히터 표('통신 끊김'에 이유) · 수동 창에 같은 이유를 보입니다
- **전원 끄기는 언제나** 됩니다

## ★ v0.7.0 — PC 끊김 정책 (공정 계속 · 끝난 뒤 안전 정지)

PC 가 끊기거나 꺼져도(프로그램 꺼짐 · PC 절전/재부팅 · 네트워크) **PLC 는 이미 받은 레시피를 끝까지 돌립니다.**
래더는 이 버전 다음에 두 PLC 의 같은 자리를 고칩니다 — 내장 시뮬레이터 · 가짜 PLC 는 먼저 새 규칙으로 맞췄습니다.

| 래더 | 지금(이전) | 새 규칙 |
|---|---|---|
| P30 행 5 중대 마스크 | `hD27F` | `hD23F` — 알람0 b6 **'PC Link Lost' 는 경고** |
| P30 행 7 안전 정지 요구 | … OR PC 통신 트립 OR … | PC 통신 트립 항 뒤에 `SEQ_RUN`(M00060) **b접점 직렬** — 시퀀서 동작 중(블록 준비 · 실행 · 일시정지 · 사이클 후 정지 예약)에는 트립이 공정을 세우지 않는다 |

- 공정 중 끊기면 **끝까지** 갑니다. 일시정지 중이면 **일시정지 그대로**(PC 가 돌아와 [Alarm Reset] 뒤 재개)
- 트립은 지금처럼 **래치**되고 PC 링크가 있을 때 **알람 리셋으로만** 풀립니다. 공정이 끝난 뒤에도 남아 있으면 그때
  **안전 정지**(밸브 · 수동 요청 끔, 펌프 · 히터 그대로). b6 은 새 알람이라 부저 · 경광등은 지금 규칙대로
- 공정 시작은 지금처럼 PC 링크가 있어야 하고, 중대 알람(비상정지 등)은 PC 가 없어도 지금처럼 세웁니다
- 대기 중(공정 아님) 트립은 지금처럼 바로 안전 정지입니다

  `leakcheck.measure_s` 최소 10 s(검사 · 실행 같게)
- **정비 카운터**: 마지막으로 본 위치에 그룹 회차(PLC 재시작으로 끝나도 회차를 맞게 센다). 블록 준비 중 중단 · 시작 때 표
  오류면 시작하지 않은 스텝은 세지 않는다. 표를 되읽어 '(PLC 번호 N)' 으로 이어받은 공정은 되읽은 표로 센다.
  `maintenance.json` 을 못 읽으면 0 으로 덮어쓰지 않고 `maintenance.bad-<시각>.json` 으로 옮긴 뒤 알리고 새로 센다(옮기지도
  못하면 그 실행에서는 저장하지 않음)
- **공정 중 경고**: 히터 이탈은 전원이 켜진 채널(`D01010` 의 그 비트)만 본다. 일시정지는 압력 상한 타이머를 멈추기만 한다
  (재개 뒤 다시 경고하지 않음). 압력 상한 즉시 중단의 이유는 실제로 보낼 때만 세우고 거절은 이벤트 로그에. 설정 검사 문구:
  `press_high_s` · `heater_dev_s` 는 0 = 넘는 즉시
- **화면**: 새 알람 창 '확인:' 을 자르지 않음(안전 문구까지 — 길면 줄바꿈). PLC 멈춤 동안에도 PC 쪽 값(누설률 점검 · 정비
  카운터 · 서버 알림)은 보이고 PLC 값으로 만든 트립 알림만 뺀다. PRM 표 칸 여백을 줄여 Mismatch 줄이 있어도 Match 칸이 다
  보인다. 운전 탭 트립 칩은 짧게 'Trip'(툴팁에 자세히). 데이터 로그 목록의 긴 작업자 · 시료는 줄임표 + title, 상세 메모는
  두 줄까지, 거르기는 Recipe / Operator / Sample

## PLC 통신 약속

### 기본

- ★ **장비 ID (`D00019`)** — PLC 가 매 스캔 자기 ID 를 씁니다(이 장비 `0x5057'PW'`,
  다른 장비 0x5045 'PE'(PEALD)). 두 PLC 는 주소표가 같아서 주소를 잘못 넣으면 레시피·밸브 명령이
  그대로 다른 장비로 갑니다(밸브 b5 는 둘 다 PV-R 이지만 배관이 다릅니다). 그래서 PC 는
  **연결 직후 가장 먼저 상태 영역을 읽어 ID 를 확인하고, 확인 전에는 PRM·하트비트·명령을 포함해
  아무것도 쓰지 않습니다.**
  - 다른 장비의 ID: 연결은 유지하되 **쓰기를 전부 막습니다(하트비트 포함)**. 화면 머리에 빨간 띠
    "다른 장비의 PLC 입니다 — 주소를 확인하세요", 이벤트 로그, 모든 조작 버튼 잠금(종료만 됨)
  - `0`(아직 ID 를 넣지 않은 PLC): 연결 때 경고 로그 한 번 + 설정 탭 표시만, 동작은 막지 않습니다.
    단 **`plc.require_device_id` 가 켜져 있으면** ID 0 도 막습니다(`missing` — 다른 장비일 때와
    똑같이 쓰기 전부 금지·연결 유지, 머리 빨간 띠 "PLC 장비 ID 가 없습니다(0) — …", 조작 잠금)
  - 로그는 상태가 **바뀌는 순간에만** 한 번 — 맞음 → 0 은 경고, 0 → 맞음은 "PLC 장비 ID 확인됨",
    다른 장비는 오류. 막힌 상태로 연결되면 "PLC 연결됨 (주소) — 장비 ID 가 맞지 않아(없어) 읽기만
    합니다" 를 경고로 남깁니다
  - 공정 시작 조건에 **'장비 ID'** 항목이 있습니다 — 막혔으면 목록이 거기서 끝나고, 시작은 사전
    판정과 같은 문구로 거절합니다
  - `plc.host` 가 비어 있으면 머리·상태줄은 "PLC 주소 없음", 명령 줄은 "PLC 주소가 없어 연결하지
    않았습니다 — 설정 탭에서 이 장비 PLC 주소를 넣으세요"
  - 매 상태 읽기에서도 확인해 ID 가 바뀌면 **즉시** 쓰기를 멈춥니다. 막힘(다른 장비·ID 없음) →
    허용으로 바뀌면 다시 연결해 처음부터(파라미터 쓰기 포함) 합니다
  - 설정 편집에서 PLC 주소를 바꾸면 확인 창이 "다시 시작하면 연결 때 장비 ID 를 확인합니다" 를 알립니다

- Modbus TCP, PLC 가 서버. **홀딩 레지스터 번호 = D 번호** (D01001 → 1001)
- FC03 읽기(한 번에 최대 125), FC06 한 개 쓰기, FC16 여러 개 쓰기(120 개씩 나눔)
- 값은 **부호 없는 16비트**로 주고받고, 부호 있는 값(히터 온도 ×0.1 ℃)만 해석할 때 바꿉니다
- DWORD 는 **아래 주소가 하위 워드** (D00024 하위, D00025 상위)
- 트랜잭션 번호를 확인하고, 시간 초과가 나면 소켓을 버립니다 —
  늦게 도착한 응답을 다음 요청의 응답으로 읽으면 엉뚱한 주소의 값을 믿게 됩니다
- 요청은 한 번에 하나(잠금). 끊기면 1 → 2 → 5 s 간격으로 다시 붙습니다

### 주기 (백그라운드 태스크 하나가 소켓을 가집니다)

| 주기 | 하는 일 |
|---|---|
| 100 ms (`plc.poll_ms`) | 상태 영역 `D00000~D00080`(81 워드)을 한 번에 읽기 |
| 250 ms (`plc.heartbeat_ms`) | `D01000`(PC 하트비트)에 +1 쓰기 (v0.4.10 에서 500 → 250 — 끊김 공백 중 하트비트 위상 몫을 0.25 s 로) |
| 500 ms | PLC 반영 영역 `D04012~D04131` 읽기 (수동 반영 + 실제로 출력 중인 설정값) |
| 1 s | 명령 영역 `D01000~D01042`(히터 목표·전원 요청) · PRM 영역 `D01100~D01124` 되읽기 |

`plc.heartbeat_ms` 는 PC 하트비트 판정(`params.pc_wdt_ms`)의 **1/3 이하**여야 합니다
(설정 검증이 오류로 알립니다).

### ★ 규칙 — 이벤트 루프에서 큰 파일·DB 를 읽지 않는다

PC 하트비트·PLC 읽기·화면 전송은 한 이벤트 루프에서 돕니다. 데이터 크기에 따라 길어지는
파일·DB 작업(트렌드 이력 조회·내보내기, 데이터 로그 목록·그래프·표, 끝 정보 짐작)을 루프에서
하면 그동안 하트비트가 멈추고, PLC 가 `PRM_PC_WDT_MS`(3 s) 뒤 **PC 통신 끊김 트립** 을 겁니다(7일 이력 조회 2.9 s 로
실제로 재현됐습니다 — 그때는 공정 중단, v0.7.0 부터는 공정은 끝까지 가고 트립이 남으면 끝난 뒤 · 대기 중이면 바로 안전 정지).

- 이런 작업은 전부 **작업 스레드**(`asyncio.to_thread`)에서 합니다. SQLite 쓰기 연결은 루프
  스레드에서만 쓰고(조회 전에 루프에서 flush), 조회는 읽기 전용 새 연결로 작업 스레드에서 합니다
- 하트비트는 읽기와 따로 **자기 태스크**에서 돕니다. 작업 스레드가 GIL 을 오래 잡지 않도록
  전환 간격을 1 ms 로 줄입니다
- 구간 제한 — 이력 조회 최대 **31일**, 내보내기 최대 **7일**(넘으면 거절하고 이유 안내).
  시작·끝은 `[지금 − 보존 일수, 지금 + 1 h]` 로 자릅니다. 묶음은 2000 이하
- **루프 지연 감시** — 100 ms 주기 작업이 늦어진 시간을 재서 500 ms 를 넘으면 그때 하던 일과
  함께 경고 로그를 남깁니다. 설정 탭 진단에 최근 최대 지연과 PC 하트비트 쓰기 간격(최대)을 보여 줍니다
- 새 기능을 넣을 때도 같습니다: 크기가 커질 수 있는 읽기·쓰기는 루프에서 하지 않습니다

★ **PC 하트비트는 화면·명령 처리와 무관하게 계속 돌아야 합니다.** PLC 는 이 값이
`PRM_PC_WDT_MS`(기본 3000 ms) 동안 안 바뀌면 PC 끊김 트립을 래치합니다(알람0 b6 경고) — 대기 중이면 바로, 공정 중이면 끝난 뒤(트립이 남아 있으면)
안전 정지합니다(v0.7.0). 트립은 PC 링크가 있을 때 알람 리셋으로만 풀리고, 프로그램은 스스로 리셋을 보내지 않습니다.

PLC 하트비트(`D00000`)가 2 s 넘게 안 바뀌면 **"PLC 하트비트 멈춤"** 으로 봅니다
(통신은 되는데 PLC 가 STOP 인 경우).

### 연결할 때마다 (처음 · 재연결)

1. 상태 영역을 읽어 **장비 ID 부터** 확인하고, `D01000~D01042` 를 읽어 다음 명령 번호 =
   읽은 `D01001` + 1 (0부터 다시 시작하면 PLC 가 무시합니다)
2. ★ **첫 쓰기는 하트비트**입니다. 하트비트 태스크를 먼저 돌린 뒤에 PRM 을 맞춥니다 —
   PRM 을 먼저 쓰면 그 왕복(약 30번) 동안 하트비트가 비어 PC 통신 끊김에 가까워집니다
3. PRM 은 **먼저 읽어서 설정과 다른 것만** 쓰고 되읽어 확인합니다. PLC 가 **공정 중**(장비 상태
   2~5)이면 쓰지 않고 경고만 합니다 — 공정 중에 RF 창·MFC 허용치·O3 한계가 바뀌지 않게. 공정이
   끝나 대기가 되면 1 s 되읽기가 맞춥니다(PLC 가 다시 시작돼 0 인 PRM 이 기본값으로 바뀐 경우도
   같은 경로로 한 번 알리고 다시 씁니다). 설정의 PRM 이 아래 규칙에 어긋나면 아무것도 쓰지 않습니다
4. PLC 반영 영역 `D04012~13 · D04050 · D04120~` 을 읽어 **'지금 수동 요청'의 기준**으로
   삼습니다. PC 영역(`D01004~`)은 기준으로 쓰지 않습니다 — PLC 는 그 영역을 지우지 않으므로
   옛 요청이 남아 있을 수 있습니다
5. 과온 알람(알람0 b9)이 래치돼 있으면 히터 전원 요청 `D01010` 을 0 으로 씁니다

**끊긴 뒤** 첫 재연결 시도는 기다리지 않고 바로 합니다. ★ 마지막으로 PC 하트비트를 쓴 뒤 **와치독(`D01100` 되읽은 값, 없으면 `params.pc_wdt_ms`) 전체**가 지나기 전까지는 빠른 재연결입니다 — PLC 는 그때까지 트립하지 않으니 그 안의 시도는 모두 공정을 살릴 수 있습니다. 이 창 안에서는 **연결 시간 초과 0.3 s**, 시간 초과로 실패하면 쉬지 않고 바로 다시(케이블 · 스위치 재시작처럼 SYN 에 답이 없는 끊김), **바로 거절된 경우에만 0.25 s** 쉽니다(붙자마자 또 끊겨도 0.25 s). 창이 지난 뒤에만 1 → 2 → 5 s. 블랙홀 끊김(바이트가 사라지고 새 연결에 답 없음) 1.2 s · 2.0 s 에서 PLC 쪽 하트비트 공백은 약 1.6 · 2.5 s 입니다(와치독 3 s). 응답 하나를
잃었을 때의 최악 하트비트 공백은 `plc.timeout_ms + plc.heartbeat_ms + 재연결 여유 500 ms` 이고,
이것이 `params.pc_wdt_ms` 이상이면 설정 검증이 오류로 알립니다(기본 1000 + 500 + 500 < 3000).
**PLC 하트비트 멈춤** — 연결은 돼 있는데 PLC 하트비트(`D00000`)가 2 s 넘게 바뀌지 않으면(PLC STOP 등, 연결 직후에는 연결 시각부터 셉니다) **명령을 보내지 않습니다**(레시피 올리기 · 수동 적용 · PRM 쓰기 포함). STOP 중에 보낸 명령은 RUN 이 되는 순간 첫 스캔이 영역을 지워 실행 없이 '처리됨(0)'으로 읽히기 때문입니다. PC 하트비트 쓰기는 계속합니다. live 의 `plc.hb_stalled` 로 화면이 값 · 알람을 `—` 로 두고 조작을 잠급니다. ★ 멈춤 동안 읽은 값은 굳은 옛 값이라 **트렌드 버퍼 · 트렌드 기록에 넣지 않고**, 데이터 로그는 끊김과 같게 값 칸을 비우고 상태 칸 `PLC 멈춤` 으로 씁니다(끊김 · 멈춤이 30 분을 넘으면 닫음).

명령 번호(`D01001`)를 쓴 뒤의 통신 오류는 '응답 없음'과 같이 "PLC 가 명령을 받았을 수 있습니다 —
상태를 확인하세요" 를 붙이고 **다시 보내지 않습니다**.

### PLC 파라미터(PRM) 값 규칙

래더 P00 은 **첫 스캔에만** 0 인 PRM 을 기본값으로 바꾸고, 그 뒤에는 PC 가 쓴 값을 타이머
설정값·비교값으로 그대로 씁니다(TON 설정값 0 = 조건이 서는 즉시 완료). 그래서 설정 불러오기·설정
편집 저장·PLC 링크가 같은 규칙으로 거릅니다.

| 설정 | 단위 | 범위 | 0 의 뜻 |
|---|---|---|---|
| `pc_wdt_ms` | ms | 1 ~ 65535 | **금지** — 첫 하트비트 뒤 곧바로 PC 통신 끊김 |
| `pump_timeout_s` | s (×10 → 100 ms 타이머) | 1 ~ 6553 | **금지** — IV-E 가 열리자마자 펌핑 시간 초과 |
| `vent_timeout_s` | s (×10) | 1 ~ 6553 | **금지** — VV 가 열리기 전에 벤트 시간 초과 |
| `mfc_timeout_s` | s (×10) | 1 ~ 6553 | **금지** — 모든 블록 준비에서 MFC 시간 초과 |
| `mfc_stable_s` | s (×10) | 0 ~ 6553 | 안정 대기 없음 |
| `valve_min_ms` | ms | 0 ~ **32767** | 최소 열림 없음 (래더는 부호 있는 16비트로 비교 — 32768 이상은 음수가 되어 최소 열림이 사라집니다) |
| `mfc_tol_sccm` | sccm | 0 이상 | MFC1 편차 감시 안 함 |
| `base_press_torr` | Torr | — | (원시값 0 이면) 공정 시작 금지 |
| `o3_max` | O3 단위 | **> 0 필수** | O3 허가(인터락 b9)가 나지 않음(래더 P30) |

정수여야 하는 칸에 소수·음수·범위 밖 값, 너무 큰 수(`1e400` 등)는 모두 검증 오류로 돌려줍니다.
`analog.raw_max` 도 **32767 이하**여야 합니다 — 래더가 아날로그 원시값과 그 비교값(베이스 압력 · 허용 편차 · 상한)을 부호 있는 16비트로 비교합니다. 시뮬레이터도 같은 비교를 합니다(타이머 설정값은 부호 없이).

PLC 는 첫 스캔에 0 인 PRM 만 기본값을 넣습니다
(WDT 3000 · PUMP_TO 600 · VENT_TO 300 · MFC_STABLE 3 · MFC_TO 60 · VLV_MIN 200).
베이스 압력·허용 편차·히터 한계·O3 상한은 **0 이면 해당 기능을 막거나 끄므로** PC 가 매번 씁니다.

### 명령 핸드셰이크 (한 번에 하나)

```
① 인자 레지스터(수동 밸브·보조·MFC·히터·SP)가 있으면 먼저 쓴다
② D01002 명령 코드
③ D01001 명령 번호 (이전 +1, 65535 다음 0)   ← 번호를 마지막에 써야 PLC 가 완성된 명령을 본다
④ D00002 가 그 번호가 될 때까지 최대 1.5 s 기다려 D00003 결과를 읽는다
```

★ 시간 초과면 **"PLC 응답 없음"** 으로 끝내고 **같은 명령을 자동으로 다시 보내지 않습니다** —
PLC 가 이미 받았을 수 있어 두 번 실행될 위험이 있습니다.

**결과(`D00003`)**: `0` 처리됨 / `1` 인터락 조건 미달(무엇이 빠졌는지 비트를 풀어서 알려 줍니다)
/ `2` 지금 상태에서 할 수 없음 / `3` 레시피 표 오류 / `4` PLC 가 모르는 명령

**명령 코드(`D01002`)**

| | | | |
|---|---|---|---|
| 1 공정 시작 | 2 일시정지 | 3 재개 | 4 사이클 끝나면 정지 |
| 5 즉시 중단 | 6 알람 확인(부저 끔) | 7 알람 리셋 | 8 펌핑 시작 |
| 9 펌핑 정지 | 10 벤트 | 11 전체 밸브 닫기 | 12 수동 적용 |
| 13 히터 적용 | 14 MFC 수동 적용 | | |

**PLC 가 거절하는 규칙**

- 시퀀서 동작 중(공정 준비·실행·일시정지·사이클 후 정지 예약)이면 9~14 → `2`
- 8 은 비상정지 **입력**(`D00008` b0) 이상 또는 알람0 b5(펌프)·b1(공압)·b3(냉각수) 래치 중 → `1`.
  이 동안은 매 스캔 펌프·배기·벤트 요청을 지웁니다. 비상정지를 푼 뒤 알람 리셋 전에도 8 은 받습니다
- 10(벤트)은 `1` 이 없습니다 — 배기 요청을 내리고 벤트 요청을 세웁니다(아래 펌핑·벤트)
- 12 는 안전 정지 요구 중 → `1`
- 2 는 시퀀서 동작 중이고 시퀀서 상태 ≠ 7(일시정지)이면 받습니다 — 블록 준비 중·이미 예약된
  때도 `0`. 다음 '정지 허용 스텝 끝 또는 블록 마지막 스텝 끝'에서 멈춥니다. 아니면 `2`
- 3 은 시퀀서 상태 7 이 아니면 `2`, 7 인데 안전 정지 요구 중이면 `1`
- 5 는 멈춰 있으면 아무것도 안 하고 `0` (PC 는 '진행 중인 공정이 없습니다'로 미리 막습니다)
- 1 은 동작 중이면 `2`, 공정 시작 허가(인터락 b3 — 레시피 표 통과 포함)가 없으면 `1`,
  허가가 있어도 그 순간 표를 다시 검사해 불합격이거나 첫 블록·첫 그룹 적재가 틀리면 `3` + 알람0 b13
- 1 s 주기 표 검사는 시퀀서가 멈춰 있을 때만 `D00028·D00029` 를 갱신하고 **알람은 래치하지
  않습니다**(올리는 도중 헛알람을 막습니다)

### 펌핑 · 벤트

- IV-E 출력은 **배기 요청 AND 펌프 허가 AND VV 닫힘** 인 동안만 켜집니다 — 조건이 빠지면
  바로 닫힙니다(비상정지로 배기 요청이 지워지면 IV-E 도 닫힘)
- 벤트(10)는 배기 요청을 내리고 벤트 요청을 세웁니다 → IV-E 가 닫히고 벤트 허가(인터락 b5 =
  시퀀서 동작 아님(공정 준비 포함) · IV-E 닫힘 입력 · IV-E 출력 꺼짐 · 비상정지 정상)가 서면
  VV 를 엽니다. **펌핑 중(IV-E 열림)에도 벤트를 누를 수 있습니다**
- PC 사전 판정: 펌핑 시작 = 비상정지 입력 정상 + 알람0 b5·b1·b3 래치 없음.
  벤트 = 시퀀서 동작 아님 + 같은 조건(래치면 PLC 가 벤트 요청을 바로 지운다고 안내)

PC 도 같은 규칙으로 버튼을 미리 잠그고 이유를 보여 주지만(편의) **최종 판단은 PLC 결과**입니다.
서버는 원격 접속의 조작 명령과 PLC 연결 끊김 중 명령을 거절합니다.
모든 명령은 (시각·명령·번호·결과·보낸 곳)이 프로그램 로그에 남습니다.

## 출력 단계 (래더 P60)

- 밸브 요청 = (시퀀서 동작 중이면 시퀀서 마스크, 아니면 `D04012`) AND 밸브 마스크
- 전구체(b0~2)와 반응물(b5)이 함께 있으면 동시 요청(인터락 b6, 알람0 b15 래치) → **모든 밸브 출력 0**
- 공정 밸브 허가(인터락 b4)가 없으면 **모든 밸브 출력 0** (펌프 정지 · IV-E 닫힘 · 안전 정지 요구 ·
  챔버 대기압). 화면은 요청(`D04012`)은 있는데 출력(`D00010`)이 없는 밸브를 **'대기'** 로 보여 줍니다
- (Powder) O3 발생기 출력 = `D04050` b9 AND O3 허가(인터락 b9). 발생기 출력이 켜져 있고
  **허가·동시 요청으로 걸러진 뒤의 요청에 PV-R 이 없으면 PV-B 를 엽니다**(렁 28 → 35 → 40).
  그래서 PV-R 을 요청했어도 공정 밸브 허가가 없거나(펌프 정지·IV-E 닫힘·안전 정지 요구·대기압)
  동시 요청이면 PV-B 가 열립니다 — 발생기가 도는 동안 O3 를 바이패스로 뺍니다
- 펌핑 시작(8)은 펌프·배기 요청을 세우고 **벤트 요청을 지웁니다** → VV 가 바로 닫히고 IV-E 가 열립니다

config.json 의 plc 를 `"host": "127.0.0.1", "port": 15401, "simulate": false` 로 바꾸고 프로그램을 실행한다
(`python run.py`). 가짜 PLC 는 프로그램과 같은 설정을 읽어야 아날로그 환산이 같다 — `--config` 가 없으면 프로그램과 같은 기본 경로
(이 폴더의 config.json, 없으면 예시 설정)를 읽고, 시작할 때 어느 설정을 쓰는지 찍는다(plc_ctl 도 같다).
`--log` 파일에는 PLC 쪽에서 본 PC 하트비트 공백(600 ms 이상) · 받은 명령(번호 · 코드) · 장비 상태 · 시퀀서 ·
알람 워드 변화가 남는다. 제어 포트는 `--port + 1`(127.0.0.1 만), 제어 파일(`--ctl-file`)에 JSON 한 줄씩 **덧붙이기(>>, Add-Content)만** 한다 —
켤 때 이미 있던 줄은 실행하지 않고(지난번에 남은 `quit` 으로 바로 꺼지지 않게), 파일이 줄어들면(`>` 로 덮어씀) 처음부터
다시 읽는다. 명령은 ASCII JSON 이라 NUL · BOM 바이트를 지우고 줄을 나눈다 — UTF-8(BOM 있어도) · UTF-16 LE/BE(PowerShell 5
의 `>>`) · 섞인 파일(cmd `echo` 로 만든 파일에 PowerShell `>>` 로 덧붙인 것)을 모두 읽는다. PowerShell 이면
`Add-Content -Encoding utf8 ctl.txt '{"op": "ping"}'` 가 가장 확실하다. `--speed` · `speed` 는 유한한 수만 받고 0.1~1000 으로
묶는다. `--config` 를 직접 줬는데 못 읽으면(경로 오타 · 읽기 오류) 예시 설정으로 넘어가지 않고 종료 코드 2 로 끝난다(plc_ctl 도).

### 2. plc_ctl 로 고장 넣기

```
python test/plc_ctl.py --port 15401 status                  (1 s 마다 — 상태 · 시퀀서 · 알람 · 입력 · 출력 · 압력 · 온도)
python test/plc_ctl.py --port 15401 faults                  (고장 목록 · 켜짐 표시)
python test/plc_ctl.py --port 15401 fault emo on            (끄기는 off)
python test/plc_ctl.py --port 15401 cut blackhole 2.0       (요청을 받고 답하지 않음 n 초)
python test/plc_ctl.py --port 15401 cut unplug 2.0          (케이블 뽑힘 — 요청도 버리고 답하지 않음 n 초)
python test/plc_ctl.py --port 15401 cut refuse 3            (연결을 끊고 n 초 동안 연결 거부)
python test/plc_ctl.py --port 15401 cut blackhole 2 --on cmd (다음 명령 번호 D01001 쓰기가 오는 그 요청부터 끊기)
python test/plc_ctl.py --port 15401 id 1234                 (장비 ID 바꾸기 — 16 진, 0x1234 · h1234 도)
python test/plc_ctl.py --port 15401 speed 20 · plant vac
```

고장 키: emo · air · n2 · cw · lid · pump_alm · leak · ot · mfc1_stuck · tc1_comm~tc3_comm · pc_hb_stop · chamber_leak(v0.7.0 — 막혀 있을 때 새는 속도 × 100) · plc_stop ·
ive_stuck · pump_nofb · o3_alm · o3_room · bp_alm · bp_nofb
(내장 시뮬레이터 조작판과 같은 목록).

`cut refuse 3` 은 **PC 통신 끊김 트립**이다 — 연결을 끊고 3 s 거부하면 다시 붙기까지 PLC 쪽 PC 하트비트 공백이 약 4 s 로
와치독(3000 ms)을 넘는다. 공정을 살린 채 끊김을 보려면 `cut blackhole 2.0` 이나 `cut unplug 2.0`(2 s 안쪽)을 쓴다.

자식(가짜 PLC · headless 프로그램)은 stdin 파이프가 닫히면 스스로 끝난다 — 시험 틀을 작업 관리자 · IDE 로 강제로 꺼도
남지 않는다. 시나리오는 시작 전에 PLC 하트비트가 정상인지 기다리고, 펌핑 시작이 2 s 안에 받아지지 않으면 한 번 더 보낸다.

### 4. 실기 시운전 때 plc_ctl

**실기에서 밸브 · 히터 · MFC 를 하나씩 확인하는 것은 프로그램의 조작 창(faceplate — 배관도에서 밸브 · 장비를 누름)으로
한다.** 조작 창은 명령 12/13/14 의 검사와 프로그램의 수동 잠금을 거친다. plc_ctl 은 **읽기 · 진단 위주**다.
```
python test/plc_ctl.py --host <PLC 주소> --port 502 status --count 1
python test/plc_ctl.py --host <PLC 주소> --port 502 read D00000 30
python test/plc_ctl.py --host <PLC 주소> --port 502 read D04012 2       (PLC 반영 영역 — 읽기만)
python test/plc_ctl.py --host <PLC 주소> --port 502 write D01004 1     (요청만 놓음 — 명령 12 를 보내야 반영)
```
`write D01004 1` 은 수동 밸브 **요청 워드만** 놓는다 — 밸브는 명령 12(수동 적용)가 와야 움직인다. `status` 는 Modbus TCP
연결을 하나 잡으므로 **PLC 의 동시 연결 수**(프로그램 · HMI 와 합쳐)를 먼저 확인한다.

쓰기는 허용 목록 안에서만 한다.

| 영역 | 쓰기 |
|---|---|
| 명령 데이터 D01004~D01042 | 그 워드의 뜻을 보이고 `y` 확인 — '명령 12/13/14 를 보내야 반영' |
| 레시피 표 D02000~D03119 | `y` 확인 |
| 하트비트 · 명령 D01000~D01003 · PRM D01100~D01124 | 옛 값 → 새 값을 보이고 `WRITE` 를 그대로 쳐야 |
| 히터 전원 · 설정 온도 D01010~D01023 | 옛 값 → 새 값 + `WRITE` — **프로그램의 다음 명령 13 이 이 값을 그대로 반영한다**(화면에서 히터 하나만 바꿔도 12 채널 전부를 이 워드에서 읽어 쓴다). 되돌리는 명령줄(옛 값)을 찍는다 |
| 그 밖(D04xxx 작업 이미지 등) | **거절**. `--raw` 를 주고 주소를 한 번 더 쳐야만 — 래더는 대기 중 D04012 · D04050 b8 을 바로 요청으로 써서 다음 스캔에 밸브가 열리거나 RF 가 켜진다(가짜 PLC 는 다음 스캔에 0 으로 되돌려 이것을 숨긴다) |

확인은 누적이다 — 허용 목록 밖이 섞인 `--raw` 쓰기도 하트비트 · 명령 · PRM · 히터 워드가 들어 있으면 주소 다시 치기와
따로 `WRITE` 를 묻는다(예: `--raw write D01099 0 2` 는 D01100 PC 와치독 3000 → 2 를 보이고 WRITE 를 쳐야).

쓰기 전에 다음이면 거절한다: 장비 ID 가 이 장비와 다름(`--force` 일 때만), 제어 프로그램이 붙어 있음(D01000 하트비트를
PRM PC 와치독(D01100)/3 + 0.3 s(최소 0.7 s, 와치독이 0 이거나 이상하면 1.3 s) 동안 0.1 s 마다 읽어 바뀜 — 프로그램의
하트비트 주기는 와치독/3 까지 허용된다. 프로그램을 끄고 쓴다), 공정 중(준비 · 공정 중 · 일시정지 · 사이클 후 정지 중).
쓰기 바로 직전에 장비 상태와 하트비트를 한 번 더 본다. **장비 ID 0**(ID 렁 전 PLC)은 PLC 로 장비를 확인할 수 없다고 알리고,
이 장비 이름(`PEALD` / `POWDERALD`)을 그대로 쳐야 쓴다(`--force` 는 진짜 다른 장비도 통과시키므로 쓰지 않는다).
값은 -32768~65535, 주소는 0~65535 만 받는다. 질문에서 입력이 끝나면(Ctrl+Z · Ctrl+D) 쓰지 않고 끝난다. 주소는 `D01004` · `01004` · `1004`
모두 같다. `--yes`(`y` 확인 생략)는 가짜 PLC 에만 듣고, `WRITE` · 주소 다시 치기는 생략하지 않는다. 고장 · 끊기 · ID 명령은
가짜 PLC 에만 보낸다.

## 내장 PLC 시뮬레이터

`plc.simulate` 가 `true` 면 프로그램 안에서 `127.0.0.1:sim_port` 에 Modbus TCP 서버를 띄우고,
PLC 링크는 그 주소에 붙습니다. **실장비와 똑같은 통신 코드를 탑니다** — 시뮬레이터용 지름길을
만들지 않았기 때문에, 여기서 통과한 것이 현장에서도 통과합니다.

20 ms 주기로 주소표 사양을 흉내 냅니다. 물리값(압력·온도 곡선)은 대략이지만
**상태 코드·결과 코드·비트 의미는 정확합니다.** 헤더에 **시뮬레이터** 칩이 항상 뜹니다.

칩을 누르면 **조작판**이 열립니다(이 PC 접속에서만). 이상 입력을 켜서 알람·인터락 동작을
확인할 수 있습니다 — 비상정지, 공압, N2, 냉각수, 리드 열림, 펌프 알람, 가스 누출, 히터 과온,
O3 발생기 알람 / 실내 O3 감지 / 바이패스 펌프 알람, 온도조절기 국번 1~3 통신 끊김, 그리고
**PC 하트비트 멈춤(시험)**, **PLC STOP(시험)**, IV-E 리미트 안 따라옴, 펌프 운전 피드백 없음, 바이패스 펌프 운전 피드백 없음. 조작판은 시뮬레이터 모드 · 이 PC 면 늘 쓸 수 있습니다(PLC STOP 으로 화면이 잠겨도 STOP 을 풀 수 있게), 스위치를 누르면 서버가 보낸 상태로 다시 그립니다.

  요구로 같은 스캔 P40 이 중단합니다(장비 상태 6 과 시퀀서 8 이 같은 스캔)

## 레시피

레시피는 `data/recipes/<이름>.json` 한 파일입니다. 다른 장비 형식(`format`)의 파일은
목록에도 올리지 않습니다 — 밸브 이름이 같아 보여도 배관이 달라 그대로 실행하면
엉뚱한 곳을 엽니다.

```jsonc
{
  "format": "POWDERALD-recipe/1",
  "name": "예시", "memo": "", "created": "...", "modified": "...",
  "blocks": [{
    "name": "블록 1",
    "repeat": 100,                      // 이 블록을 몇 사이클 돌릴지
    "mfc_sccm": [0, 0],        // MFC1 · MFC2
    "o3": 80,
    "steps": [
      { "name": "전구체", "time_ms": 100, "valves": ["PV-1"], "pause_ok": false },
      { "name": "퍼지",   "time_ms": 3000, "valves": [],       "pause_ok": true }
    ]
  }],
  "groups": [ { "from_block": 1, "to_block": 2, "repeat": 10 } ]   // 블록 묶음 반복 (겹칠 수 없음)
}
```

한계: 스텝 100 · 블록 10 · 그룹 5 · 스텝 시간 20~3,276,700 ms ·
블록 반복 1~1,000,000 · 그룹 반복 **1~32,767**.

- ★ **그룹 반복 32,767** — 그룹 항목은 한 워드인데 래더(XGK)의 비교 명령은 **부호 있는 16비트**라
  32,768 이상은 음수로 읽힙니다. P40 은 그룹을 불러올 때 '반복 < 1' 이면 레시피 오류(SEQ_RCP_ERR)로
  모든 밸브를 닫고 중단하므로, [1–2 ×100, 3–4 ×40000] 같은 레시피는 그룹 1 을 다 돈 뒤 **증착
  중간에** 섭니다. 한계는 PLC 표 정의 옆(`addresses.RCP_GROUP_REPEAT_MAX`) 상수 하나이고
  검증 · 화면 · 이 문서가 그것을 씁니다. 시뮬레이터도 표의 한 워드 값(그룹 시작·끝·반복, 블록
  첫·끝 스텝)을 부호 있게 읽어 래더와 같은 곳에서 멈춥니다
- 반복 그룹 키는 **`from_block` / `to_block`**(서버 · 저장 파일 · PLC 표 · 화면 모두 같음).
  옛 파일의 `from` / `to` 는 불러올 때 바꿔 읽고, 저장은 새 키로만 합니다

### 검증 (서버에서만 합니다)

화면은 편집한 내용을 `recipe_validate` 로 보내고 **오류·경고·예상 시간을 받아 그리기만**
합니다. 화면이 따로 계산하면 두 값이 달라지고, 운전자는 어느 쪽을 믿어야 할지 모릅니다.

오류(올릴 수 없음)와 경고(올릴 수 있지만 확인이 필요함)를 구분합니다.

- ★ **값 형식부터** — 불러올 때 · 저장할 때 · 검증할 때 모든 필드의 형식(정수 · 실수 · 불 · 문자열 ·
  목록 · 사전)을 보고, 틀리면 계산하지 않고 **검증 오류**로 돌려줍니다(예외가 아니라). 반복 · 시간
  같은 정수 칸에 소수가 오면 조용히 자르지 않고 오류입니다(반복 2.5 · 150.7 ms). 너무 큰 수 ·
  무한대 · 빈 값(null)도 오류입니다. 형식이 틀린 레시피는 PLC 표를 만들지 않습니다
- 편집기는 모든 속성 값을 이스케이프해서 넣습니다 — 조작된 레시피 파일(USB 로 받은 것 등)의
  `1"><img onerror=…>` 가 운전 PC 화면에서 스크립트로 돌아 로컬 권한으로 명령을 보내지 못하게

- 오류 — 한계 초과, 스텝·블록이 없음, 이름이 비었거나 너무 김, 시간이 범위 밖,
  모르는 밸브 태그, 전구체와 반응물을 한 스텝에서 함께 여는 것, 그룹 범위가 잘못됐거나
  서로 겹치는 것, 설정값이 범위 밖(MFC 풀스케일·O3 상한·PLC 가 막는 0),
  풀스케일·상한이 **미정**인데 0 이 아닌 값을 쓴 것(원시값으로 바꿀 수 없습니다 — 풀스케일이 없는
  MFC 는 PLC 표에 0 으로 들어가 **그 가스 없이** 돕니다. 블록 준비는 MFC1 만 봅니다).
  O3 를 쓰는 블록인데 **O3 풀스케일(`o3.full`)이 비었으면** 오류 — PLC 의 O3 상한이 0 이 되어 O3 허가가 나지 않습니다
- 경고 — 새로 열리는 밸브가 있는 스텝이 `valve_min_ms` 보다 짧아 **PLC 가 늘리는 것**,
  60 s 를 넘는 스텝(PLC 가 100 ms 단위로 내림), 퍼지 스텝이 없는 것,
  보조 밸브만 열고 짝이 되는 밸브를 안 연 것, PV-R 스텝이 있는데 블록 O3 설정이 0 인 것

### 시간 계산

`valve_min_ms` · `mfc_stable_s` 가 설정에 없으면 PLC P00 기본값과 같은 표
(`addresses.PRM_DEFAULTS` — 200 ms · 3 s)를 씁니다. 시간 계산 · '최소 열림보다 짧아 PLC 가 늘립니다'
경고 · PLC 쓰기가 모두 이 표 한 곳에서 가져옵니다(예전에는 검증만 0 으로 봐 경고가 안 떴습니다).

스텝 실제 시간 = 새로 열리는 밸브가 있으면 `max(설정, valve_min_ms)`,
60 s 를 넘으면 100 ms 단위로 내림. 블록 시간 = 준비 시간(MFC 안정 `mfc_stable_s`) +
1회차 사이클 + (반복-1) × 이후 사이클. 전체 = 블록 합 + 그룹 반복분.
**진행 화면의 남은 시간도 같은 함수로 계산합니다** — 두 값이 어긋나면 안 됩니다.
사이클 후 정지가 예약돼 있으면(장비 상태 5, 또는 일시정지 중에 예약한 것) **이번 사이클의 남은
시간만** 셉니다.

### PLC 표로 바꾸기 · 올리기

레시피 → `D02000~D03119`(1120 워드).

| 영역 | 내용 |
|---|---|
| D02000~04 | 스텝 개수 · 블록 개수 · 그룹 개수 · 합계 · 레시피 번호 |
| D02100~ | 스텝 n: 8 워드 (밸브 비트 32 · 시간 ms 32 · 플래그) |
| D02900~ | 블록 n: 16 워드 (시작 스텝 · 스텝 수 · 반복 32 · 설정값) |
| D03100~ | 그룹 n: 4 워드 (시작 블록 · 끝 블록 · 반복) |

- 합계 = `D02000~D03119` 중 `D02003` 을 뺀 모든 워드의 합의 하위 16비트
- 레시피 번호 = 레시피 내용(메모·시각 제외)의 CRC32 하위 16비트(0 이면 1) —
  **데이터 로그와 PLC 가 들고 있는 것을 대조**하는 데 씁니다
- 올리는 순서: **본문 먼저, 헤더(개수·합계)를 마지막**. PLC 는 1 s 마다 헤더를 보고
  표를 검사하므로, 헤더를 먼저 쓰면 아직 안 올라온 본문으로 검사해 불합격이 뜹니다
- 올린 뒤 **되읽어 워드 단위로 비교**하고, PLC 의 검사 결과(`D00029`)를 3 s 까지 기다립니다
- 보낸 합계와 PLC 가 계산한 합계가 다르면 **실패로 보고**합니다 —
  표는 이미 올라갔을 수 있으므로 "올라갔다"고 말하지 않습니다
- 공정 중에는 올리지 않습니다. PLC 는 시작할 때 작업본(`D05000~`)으로 복사해 돌기 때문에
  실제 영향은 없지만, 화면과 실제가 달라 보이기 때문입니다

## 공정 시작 흐름

시작은 명령 하나가 아니라 흐름입니다.

```
레시피 검증 → PLC 표 올리기 → 베이스 압력 대기 → 명령 1(공정 시작)
```

- ★ 시작 흐름은 러너가 쥐는 **백그라운드 태스크**로 돕니다. `process_start` 는 바로 돌아오고
  결과는 흐름이 끝날 때 알립니다 — 베이스 압력 대기(최대 `process.base_wait_timeout_s`) 동안에도
  같은 연결의 [대기 취소] · 알람 확인 · 벤트 · 펌핑 정지 · 전체 닫기가 **바로** 처리됩니다
- 흐름 동안(올리기·대기·명령 1)은 **레시피 선택 · 올리기 · 지금 선택된 레시피 덮어쓰기·삭제·
  이름 바꾸기 · 설정 저장**을 거절하고, 레시피 탭의 올리기·시작 버튼도 잠급니다
- 흐름은 **시작을 누른 순간의 스냅샷**(이름 · 레시피 · 표 · 번호 · 합계)으로만 진행하고,
  로그 · 데이터 로그 · 진행 표시 · 끝 기록도 그 스냅샷을 씁니다(공정 중에 다른 레시피를 골라도 그대로)
- 명령 1 을 보내기 직전에 `D00028`(합계) · `D00029`(검증 통과) · 표 머리의 레시피 번호를 다시 읽어
  스냅샷과 같을 때만 보냅니다
- 흐름 안에서 어떤 예외가 나도 단계(phase)를 대기로 되돌리고 로그를 남깁니다
- ★ v0.8.1: 공정 중 시작 조건은 화면용이다 — `progress()` 는 live(5 Hz)와 데이터 로그 줄이 부르므로 공정 중 그 계산에서
  예외가 나면 `checks = []` 로 내고 경고는 같은 예외 종류마다 한 실행에 한 번만 남긴다(live · 데이터 로그를 깨지 않게).
  공정이 아닐 때는 시작 판단이라 예외를 삼키지 않는다
- 시작 조건은 **서버가 판정**하고 화면은 항목과 현재 값을 받아 그립니다:
  PLC 연결·하트비트 / 장비 상태 / 중대 알람 없음 / 펌프 / 공정 밸브 허가 /
  베이스 압력 / 레시피 검증 / O3 허가 / **O3 발생기 켜짐**(O3 를 쓰는 레시피만) / (설정으로 켜면) 히터 안정
- 히터 안정은 사용 채널마다 **±`band_c` 안에 `stable_s` 초 이상 계속** 머물렀을 때입니다(샘플링 루프가 채널마다 들어온 시각을 기록). 온도조절기 통신이 없는 국번의 채널은 `통신 없음` 으로 안정이 아닙니다
- O3 끄기 뒤 바이패스 라인 닫기 예약(지연)이 남아 있으면 시작 흐름 첫머리에 취소합니다 — 흐름 중에 닫히면 O3 허가가 빠져 시작이 거절되거나 시작 직후 알람1 b3 로 중단됩니다
- ★ **O3 발생기 켜짐** — 래더의 공정 시작 조건(ILK_PROCESS_OK)은 O3 허가(인터락 b9 — 바이패스 펌프 ·
  IV-B · 5 s · O3 알람 없음 · `PRM_O3_MAX` > 0)만 보고 **발생기 요청(`D04050` b9)은 보지 않습니다**
  (래더 P30). 그래서 발생기만 꺼진 채 시작하면 O3 없이 공정이 돕니다. 레시피에 O3 설정이 0 보다
  큰 블록이 있으면 보조 출력 `D00014` b9(발생기)를 시작 조건에 넣고, 꺼져 있으면 운전 화면에
  [O3 라인 켜기] 버튼을 보입니다. O3 설정이 모두 0 인 레시피는 영향이 없습니다
- **베이스 압력만은 시작을 막지 않습니다** — 기다리면 채워지는 조건이라 대기로 처리합니다
- 대기 중 PLC 가 끊기거나 안전 정지 요구·중대 알람이 생기면 대기를 접습니다. ★ 입력으로도 봅니다 — 펌프 운전 입력이 꺼지거나 IV-E 열림이 꺼지거나 챔버 대기압이 켜지거나 장비 상태가 대기가 아니면(판넬 · 다른 경로의 벤트 · 펌핑 정지 포함) 접습니다. 이 PC 에서 **벤트 · 펌핑 정지 · 전체 닫기**를 보내면 대기를 먼저 취소합니다 — 대기가 살아 남으면 나중에 누가 펌핑할 때 운전자 없이 공정이 시작됩니다.
  운전자가 [대기 취소]로 멈출 수도 있습니다
- 최종 판단은 PLC 결과입니다. 결과 1(인터락)이면 **빠진 조건을 풀어서** 알려 줍니다

  허가와 상관없이 보낸다. 판단은 명령 잠금 안에서 새로 읽은 반영 영역으로
- **같은 요청 무시**: 열기인데 이미 요청 있음 · 닫기인데 요청 없음이면 보내지 않고 info 알림('이미 … — 다시 보내지 않았습니다').
  명령 12 를 쓰는 다른 수동 명령(PCV · RF · O3)도 바뀌는 것이 없으면 보내지 않는다(기준이 PLC 반영 영역이라 믿을 수 있다).
  ★ 명령 13(히터)은 예외 — 기준이 PC 요청 워드(`D01010`)라 PLC 재시작 뒤 실제 출력과 다를 수 있어 '같은 값' 이라고 막지 않는다
- **결과 글은 되읽은 출력으로**: 명령 12 결과 0 은 '받았다' 는 뜻일 뿐이다 — 보낸 뒤 상태 영역을 다시 읽어 'PV-1 열림 확인' ·
  'PV-1 열기 요청됨 — 출력이 아직 꺼져 있습니다(…)' · 'PV-1 닫힘 확인'. 반영 안 됨(PLC 가 지움)은 예전 그대로
- **Pending 알림**: 연결됨 · 공정 아님 · 허가를 기다리는 수동 밸브 요청이 있으면 Program Notices 에 '수동 밸브 요청이 허가를
  기다립니다: PV-1 — … 필요 없으면 그 밸브 [Close] 또는 [Close All Valves]'
- **Pumping Start 확인**: 수동 밸브 요청이 남아 있고 Valve Permit 이 없으면 명령줄 · 조작 창 모두 확인 창('펌핑으로 Valve Permit 이
  생기면 이 밸브가 바로 열립니다 — 먼저 Close …')
- `live.manual` 에 `valve_permit` · `valve_permit_missing`(끊기면 False · [])

- **밸브** — 잠금 해제(5분)를 켜야 누를 수 있고, 공정이 시작되면 서버가 다시 잠급니다.
  요청과 실제 반영을 나란히 보여 줍니다(요청했는데 안 열린 것은 `대기`).
  전구체와 반응물을 함께 여는 요청은 PC 가 먼저 막습니다 —
  PLC 도 둘 다 막고 중대 알람을 냅니다
- **PC 는 수동 요청을 따로 기억하지 않습니다.** PLC 는 전체 닫기·공정 시작·안전 정지 요구·
  챔버 대기압에서 **내부 사본(`D04012~13`·`D04050`)만** 지우고 PC 영역(`D01004~`)은
  그대로 둡니다. 그래서 명령 12 를 보낼 때마다 명령 잠금 안에서 **반영 영역
  `D04012~D04131` 을 새로 읽고, 거기에 이번 변경만 얹어** `D01004~07 · D01008 ·
  (O3) D01042` 를 전부 쓴 뒤 보냅니다.
  밸브 하나를 눌러도 O3 설정·다른 값은 지금 값 그대로입니다
- 명령 12 가 `0` 이어도 반영 영역을 다시 읽어 **반영 안 된 비트가 있으면 이유와 함께** 알립니다
  (대기압 입력이면 PLC 가 밸브 요청을 바로 지웁니다)
- 명령 없이 반영 비트가 줄면 **"PLC 가 수동 요청을 지웠습니다 — PV-2 (안전 정지 요구)"** 처럼
  로그를 남깁니다
- 화면의 **요청 = `D04012`·`D04050`, 출력 = `D00010`·`D00014`** 입니다. 요청했는데 출력이 안
  나간 것은 `대기`(배관도는 점선)로 따로 보여 줍니다
- **MFC** — 풀스케일이 미정이면 거절합니다. 명령 14 도 `D04121~` 현재 값에 이번 변경만 얹어
  MFC 개수만큼 전부 씁니다(공정 뒤 한 채널만 바꿔도 나머지는 0 그대로)
- **히터** — 설정 온도·전원(`D01010`·`D01012~` 가 PC 요청, 명령 13 때 PLC 가 복사).
  화면 값은 명령 영역을 1 s 마다 되읽은 것이고 명령 13 성공 직후에는 쓴 값으로 바로 바뀝니다.
  전원 스위치는 서버가 가진 현재 값 기준으로 목표 상태를 보내고 응답까지 잠급니다.
  과온 한계가 없는 채널은 설정·전원 켜기를, **온도조절기 통신이 없는 채널은 전원 켜기를**
  거절합니다(끄기는 언제나). 과온 알람(b9)이 새로 켜지면 PLC 가
  전원 묶음을 끄고, **PC 도 `D01010` = 0** 을 써서 리셋 뒤 다른 채널 적용이 꺼진 채널을
  되살리지 않게 합니다(래치 중 켜기는 거절). 명령 13 이 거절되면 방금 쓴 값을 되돌려 씁니다.
  공정 중에는 못 바꿉니다
- **O3 라인** — 켜기는 바이패스 펌프 → IV-B → (5 s 뒤 허가) 발생기 순서로 요청합니다.
  끄기는 **발생기를 먼저 끄고**, `process.o3_off_delay_s` 만큼 기다려 배관에 남은 O3 를
  뺀 뒤 바이패스 라인을 닫습니다. 지연은 **서버 타이머**가 셉니다(화면을 닫거나 새로 고쳐도
  진행). 그 사이 공정이 시작됐거나 PLC 가 라인을 지웠으면 취소하고 로그만 남깁니다.
  켜기 전에 PLC 에서 되읽은 `PRM_O3_MAX` 가 0 보다 큰지 봅니다 — **O3 한계가 0 이면 O3 허가가
  나지 않아** 발생기가 켜지지 않습니다(래더). O3 설정이 0 이면 켜도 O3 가 나오지 않으므로 먼저 넣게 합니다
- **전체 밸브 닫기** — O3 라인이 켜져 있으면 확인 창이 "O3 라인도 한꺼번에 꺼집니다"를
  알립니다(순서대로 끄려면 O3 라인 끄기를 먼저)

- PIN 이 없으면 처음 편집하려 할 때 새 PIN(숫자 4~8자리)을 두 번 입력해 정합니다.
  바꾸기는 현재 PIN 을 확인한 뒤에 합니다
- 잠금 해제는 **이 PC(루프백) 연결에서만** 됩니다. 서버가 무작위 토큰을 만들어 **그 웹소켓
  연결에만** 붙입니다 — 다른 창·원격 연결은 같은 토큰으로도 통하지 않습니다
- 관리자 조작 없이 **10 분**, **공정 시작**, **[잠금]** 중 하나면 다시 잠깁니다
- **5 번 틀리면 5 분** 동안 입력을 막습니다. 성공·실패·잠금은 프로그램 로그에 남습니다(PIN 값 제외)

### PIN 을 잊었을 때

1. 프로그램을 끕니다(공정 중이 아닐 때)
2. exe 옆 `data/admin_pin.json` 을 지웁니다
3. 다시 켜고 설정 탭에서 **[PIN 정하기]** 로 새로 정합니다

## 트렌드 이력

- 1 Hz 간격은 `time.monotonic` 으로 셉니다(저장하는 시각만 `time.time` — PC 시계를 돌려도 기록이 비지 않음)
- 1 Hz 샘플을 날짜별 SQLite(`data/trend/YYYYMMDD.db`, 표준 sqlite3, WAL, 5 s 마다 묶어 커밋)에 쌓습니다
- 열은 장비 구조로 고정입니다(압력 · MFC 현재/설정 · 히터 CH1~12 현재/설정 · 장비 전용 값 ·
  밸브/보조 출력 워드 · 장비 상태 · 블록·스텝). 설정이 바뀌어도 표 구조가 안 바뀝니다
- 값은 공학 단위를 **고정 배율 정수**(온도·유량·전력·개도·O3 ×10, 압력은 실수)로 둡니다 —
  환산을 나중에 바꿔도 이력이 변하지 않습니다. 하루 10 MB 안팎
- `log.trend_keep_days`(기본 90) 지난 파일은 기동할 때 지웁니다. 쓰기 실패는 로그만 남기고
  화면·공정을 막지 않습니다. 디스크 여유가 1 GB 아래면 경고합니다
- 트렌드 탭 **[실시간 | 이력]** — 이력: 시작·끝 시각(1 h · 6 h · 24 h · 7 일), 계열 선택,
  끌어서 확대 · [되돌리기], 커서 값. 서버가 구간을 최대 2000 묶음(최소·최대·평균)으로 줄여
  보냅니다. 프로그램이 꺼져 있던 구간은 선을 잇지 않습니다. 압력은 로그 축(0 이하 값은 그리지도
  축 범위에 넣지도 않습니다). 조회마다 번호를 붙여 **가장 최근 요청의 응답만** 그립니다
- 실시간 트렌드는 사용하는 히터 채널을 모두(12 개까지) 그립니다. PLC 가 끊기면 띠 값은 `—`

  **아직 쓰는 중인 파일**(종료 뒤 5 s 꼬리 포함)은 짐작하지 않고 `기록 중` 으로 보여 줍니다

- ★ **CSV 읽기** — 작업 스레드에서 돌아도 이벤트 루프(PC 하트비트)를 멈추지 않게: 텍스트 모드 줄 읽기(8 KB)는 읽을 때마다 GIL 을 놓았다가 바로 다시 잡아 루프가 차례를 못 받고(convoy), 줄 전체를 list 로 모았다 버리는 것도 100~200 ms 멈춥니다. 그래서 **1 MiB 바이너리 읽기 + 증분 디코더(utf-8-sig) + 줄 생성기**를 `csv.reader` 에 넣고(따옴표 안 줄바꿈도 처리), 그래프는 줄을 모으지 않고 숫자만 `array('d')` 와 구간에 모아 묶습니다. 표는 offset 까지 건너뛰며 그 쪽 줄만 모으고 총 줄 수는 세기만, 목록의 메타 짐작은 줄 수(바이너리 줄바꿈 세기 — 따옴표 안은 빼고)와 파일 끝에서 거꾸로 읽은 마지막 줄만 봅니다. 그래프 · 트렌드 이력 JSON 은 값을 **유효 숫자 5 자리**로 줄이고 줄 200 개씩 나눠 만듭니다(C 인코더는 한 번 부르는 동안 GIL 을 놓지 않는다). 트렌드 내보내기는 1 MiB 쓰기 버퍼
- 화면에서 지우기는 없습니다. 정리는 보존 기간(`log.datalog_keep_days`)으로만 합니다

**포트** — ★ v0.4.12: 서버가 들을 소켓을 **먼저 묶고**(확인이 곧 실제 bind) 그 소켓을 uvicorn 에 넘깁니다
(`Server.run(sockets=…)`). 주소는 서버와 같게 `getaddrinfo`(AF_UNSPEC · AI_PASSIVE)로 풀어 주소마다 하나씩 묶습니다 —
`::` · `::1` 은 IPv6 로(IPv6 는 V6ONLY), `localhost` 는 풀린 주소 모두(예전에는 IPv4 로만 확인해 `::` · `::1` 을 늘 '사용 중'으로,
`localhost` 를 127.0.0.1 로만 봤다). 소켓 옵션도 서버와 같습니다(POSIX 는 SO_REUSEADDR — 빠르게 다시 시작해 TIME_WAIT 만 남은
포트도 열립니다. Windows 는 asyncio 가 SO_REUSEADDR 를 켜지 않고, TIME_WAIT 만 남은 포트는 옵션 없이도 열립니다). 정말 다른
프로그램이 쓰고 있으면 5 s 다시 시도한 뒤 **다른 포트로 조용히 옮기지 않고** 이유를 알리고 멈춥니다 — 서버 · PLC 링크 ·
시뮬레이터(lifespan)를 띄우기 **전에**(창 모드 · headless 같게. 예전에는 uvicorn 이 lifespan 뒤에 bind 해 PLC 링크가 먼저 돌았고,
bind 실패는 SystemExit 라 창 모드에서 잡히지 않았다). `server.host` 는 빈 값(= 기본 127.0.0.1) · `localhost`(대소문자 상관없음) ·
IP 주소만 받습니다(이름 · 앞뒤 공백 · 틀린 주소는 설정 오류). 모든 주소에서 받으려면 `0.0.0.0`(IPv4) 또는 `::`(IPv6).
★ v0.4.13: 묶은 소켓은 **바로 listen** 합니다(POSIX 는 SO_REUSEADDR 라 listen 전에는 두 번째 실행도 같은 포트를 묶을 수
있었다). 그래서 창은 '포트가 열렸나' 대신 `/health` 가 답할 때까지 기다립니다. 이 PC 에서 만들 수 없는 주소 family(예: `::1` 은
풀리는데 IPv6 소켓이 없는 PC 의 `localhost`)는 asyncio 처럼 건너뛰고, 하나도 못 묶을 때만 실패(이유는 실제 오류)로 봅니다.
★ v0.4.13 Windows 는 **SO_EXCLUSIVEADDRUSE** 로 묶습니다. 옵션 없이 모든 주소(0.0.0.0:P)로 들으면 같은 사용자의 다른 프로그램이
127.0.0.1:P 를 (옵션이 없어도) 묶을 수 있고, 그러면 127.0.0.1:P 접속을 그쪽이 받았습니다(확인한 것 — 같은 주소끼리는 옵션 없이도
10048 · 10013 으로 거절, 127.0.0.1 로 들을 때 다른 쪽이 0.0.0.0 · LAN IP 를 묶어도 127.0.0.1 접속은 우리가 받음).
SO_EXCLUSIVEADDRUSE 면 그 묶기가 10013 으로 거절되고, 빠른 다시 시작(우리 쪽 TIME_WAIT 만 남은 포트)도 바로 다시 묶입니다.
★ v0.4.14: 5 s 다시 시도는 **사용 중**(EADDRINUSE · EACCES · 10048 · 10013)일 때만입니다. 그 밖(IPv6 없는 PC 의 `::1` — 97 ·
10047, 이 PC 에 없는 IP — 99 · 10049, 이름을 못 풂)은 기다려도 안 바뀌므로 바로 실제 이유로 알리고 멈춥니다('다른 프로그램이 쓰고
있습니다'는 사용 중일 때만). v0.4.15: POSIX 는 EADDRINUSE 만 다시 시도합니다(EACCES 는 권한 없는 포트 — 80 등). 13 · 10013 으로
끝나면 문구에 '또는 쓸 권한이 없거나 예약된 포트(Windows: `netsh int ipv4 show excludedportrange protocol=tcp`)'를 더합니다
(v0.4.16: 이 판단을 '이 PC 에 없는 주소' 문구보다 먼저 — POSIX 의 13 이 주소 문구로 나오던 것). `--selftest` 는 운영체제가 고른
빈 포트로 띄웁니다(기본 포트 + 50 이 쓰이고 있으면 실패할 수 있던 것).
서버 시작(lifespan)이 실패하면 원인을 로그에 쓰고(v0.4.15: 창의 알림에도 그 예외 글), 창은 20 s 를 기다리지 않고 바로 알리며 headless 는

## 화면 ↔ 서버 통신 약속

WebSocket 하나(`ws://<host>:<port>/ws`)로 주고받습니다. 트렌드 이력만 HTTP 입니다.

★ **상태의 주인은 서버입니다.** 화면은 값을 지어내지 않습니다.
PLC 가 끊기면 모든 값이 `null`(화면에서 `—`)이고 명령 버튼이 잠깁니다.
**값 없음과 0 을 반드시 구분합니다** — 끊긴 채로 0 을 보여 주면 "유량이 0"으로 오해합니다.

| `live` | 5 Hz | 아래 |
| `log` | 로그 한 줄 | `level` `msg` `ts` |

### 화면 → 서버

`{"cmd": "..."}` 형태입니다. 이번 단계의 명령:

| 무리 | 명령 |
|---|---|
| 배기·알람 | `pump_start` `pump_stop` `vent` `all_close` `alarm_ack` `alarm_reset` |
| 레시피 | `recipe_validate` `recipe_load` `recipe_save` `recipe_rename` `recipe_delete` `recipe_select` `recipe_upload` `plc_recipe_read` |
| 공정 | `process_start` `process_cancel_wait` `process_pause` `process_resume` `process_stop_after_cycle` `process_abort` |
| 수동 | `manual_unlock` `manual_valve` `manual_mfc` `manual_heater` `manual_o3` (끄기 마무리는 서버 타이머) |
| 관리자·설정 | `admin_setup` `admin_unlock` `admin_lock` `admin_change` `config_preview` `config_save` (설정 명령은 잠금 해제 토큰 필요) |
| 이력 | `trend_export` `open_folder` |
| 그 밖 | `sim_fault`(시뮬레이터 조작판) `alarm_popup_close` `exit` |

`recipe_validate` 의 답은 `recipe_check`(오류·경고·요약), `recipe_load` 의 답은 `recipe`,
`recipe_save` 의 답은 `recipe_saved`(`ok` · 저장한 `name` · 거절 `why`)입니다. 모두 **보낸 화면에만**
돌려줍니다. 화면은 `recipe_saved` 가 성공으로 온 뒤에만 '저장됨'으로 바꿉니다(거절이면 편집 유지).
`recipe_rename` 의 답은 `recipe_renamed`(`ok` · `old` · `new` · 거절 `why`), `recipe_delete` 의 답은 `recipe_deleted`(`ok` · `name` · `why`) — 화면은 **ok 일 때만** 이름을 바꾸거나 편집기를 비웁니다(거절된 새 이름으로 다음 저장이 남의 레시피를 덮지 않게, 지워지지 않은 레시피의 편집을 잃지 않게). `recipe_validate` 에 붙인 요청 번호 `req`(0 ~ 2³¹ 정수)는 `recipe_check` 에 그대로 돌아오고, 화면은 **마지막 요청의 답만** 씁니다. `alarm_history`(읽기 전용, 원격도) 의 답은 `alarm_history`(`items` · `ver`) — live 의 `alarm_hist_ver` 가 바뀌면 화면이 다시 받습니다(접속 때 한 번만 받으면 그 뒤 이력 탭이 멈춥니다).

**원격(루프백이 아닌 접속)의 조작 명령은 전부 거절합니다.** 주소를 판정할 수 없으면
원격으로 봅니다(안전한 쪽으로 틀립니다). 거절할 때는 항상 `notice` 로 이유를 돌려줍니다.
원격에서 되는 것은 읽기뿐입니다 — `recipe_load` · `recipe_validate`(레시피 보기 · 검증 · 요약) · `alarm_history`.
저장 · 올리기 · 삭제 · 이름 바꾸기 · 선택 · 시작 · `alarm_popup_close` 는 그대로 거절합니다.
원격 화면의 알람 창은 명령을 보내지 않고 **그 화면에서만** 닫고, 그때 없던 알람이 새로 오면 다시 뜹니다.

#### ★ v0.8.0 — 요청 번호(rid) · 응답 끝(done)

- 화면은 보낼 때마다 `rid`(1 부터 늘어나는 정수, 2³¹ 전에 1 로)를 붙인다(`app.send` 가 rid 를 돌려준다 — 못 보내면 0).
  레시피 검증의 `req` 는 다른 번호 그대로
- 서버는 `rid` 가 정수(0 < rid < 2³¹, bool 아님)면 그 명령의 처리가 끝났을 때(예외 · 원격 거절이어도) **그 연결에만**
  `{"type": "done", "rid": rid, "cmd": 명령 앞 40 자}` 를 보낸다. rid 가 없거나 이상하면 done 없음(시험 도구 · e2e)
- 그 연결에 대한 답(`ws` 를 준 `notice`)에는 `rid` 를 붙인다(`connection.CURRENT_RID`). 방송 알림에는 rid 가 없다
- 화면의 진행 중 잠금(`core.busy` — key `cmd:명령` · `valve:태그` · `heater:채널` · `mfc` · `pcv` · `rf` · `o3` · `unlock` ·
  `leak` · `sim:키`)은 done 으로 풀리고, 8 s 지나면 저절로, 서버 끊김 · 다시 연결 때 모두 풀린다
- ★ v0.8.1: `manual_unlock` 도 그 연결에 info 알림(rid 붙음) — 켤 때 '수동 조작 잠금 해제 — 5분 뒤 · 공정이 시작되면 다시
  잠깁니다', 끌 때 '수동 조작 잠금'. 조작 창은 done 이 왔는데 그 rid 의 알림이 없었으면 결과 줄('기다리는 중')을 비운다

★ **무거운 조회 문**(`heavy.py`) — 데이터 로그 목록 · 그래프 · 표, 트렌드 이력 · 내보내기는 문 하나를 지나 작업 스레드에서 돕니다. **서버 전체 동시 2 개, 그중 원격은 합쳐서 1 개**. 원격 칸이 차 있으면 기다리지 않고 바로 **429** `{error: "다른 조회가 끝난 뒤 다시 시도하세요"}`, 로컬은 줄을 섭니다. 작업 스레드에서도 CSV 풀기 · JSON 만들기는 GIL 을 잡아, 여러 개가 한꺼번에 돌면 루프가 차례를 못 받아 PC 하트비트가 멈춥니다. 응답 JSON 도 스레드에서 바이트로 만듭니다. 그래프는 (경로 · 크기 · 수정 시각)으로 최근 4 개를 캐시합니다(같은 파일 두 번째는 다시 풀지 않고 문도 지나지 않습니다 — 쓰는 중인 파일은 빼고). `/api/trend`(실시간 버퍼)는 로컬이면 문 밖 작업 스레드에서, 원격이면 같은 원격 칸을 지납니다.

### ★ 접속 보안 (출처 · Host · 크기)

- **Host** 는 IP 주소(v4/v6) 또는 `localhost` 여야 합니다 — 도메인 이름이면 HTTP·WebSocket 모두
  거절합니다(DNS 재바인딩으로 외부 페이지가 명령·이력·데이터 로그에 닿지 못하게)
- **WebSocket Origin** 이 있으면(브라우저는 항상 보냅니다) 그 `host:port` 가 요청의 Host 와 같아야
  합니다. 다르면 연결을 받지 않고 로그 한 줄(출처만, 잘라서). 운전 PC 브라우저에 열린 아무 웹
  페이지가 `ws://127.0.0.1:포트/ws` 로 운전 명령을 보내지 못하게 합니다. Origin 이 없는 연결
  (브라우저가 아닌 도구)은 루프백 = 운전자, 그 밖 = 보기 전용 규칙 그대로
- WebSocket 메시지는 최대 **64 KiB**(uvicorn `ws_max_size`) — 넘으면 연결을 닫습니다(아래 '원격 접속 한도')
- `cmd` 는 문자열이고 **등록된 명령 이름**일 때만 처리합니다. 모르는 이름·원격 거절은 앞 40자만,
  줄바꿈·제어 문자를 지우고, 같은 연결에서 초당 한 번만 로그에 남깁니다
- 로그는 모든 줄에서 줄바꿈·제어 문자를 지우고 길이를 자릅니다 — 가짜 '처리됨' 줄을 끼워 넣거나
  거대한 입력으로 로그를 부풀리지 못하게
- 명령 처리 중 예상 못 한 예외는 로그·알림만 하고 연결은 유지합니다

### ★ 원격 접속 한도 (속도 · 크기 · 연결 수 · 느린 화면)

원격(보기 전용) 접속이 **장비(PC 하트비트)와 이 PC 화면에 영향을 주지 못하게** 연결 하나가 서버에 시킬 수
있는 일의 양을 정합니다. 값은 `connection.py` 머리의 상수 한 곳에 있습니다.

| 한도 | 값 | 넘으면 |
|---|---|---|
| 원격 메시지 속도 | 초당 5개 · 순간 10개(토큰 버킷) | JSON 을 풀기 전에 버리고 개수만 셈. 10 s 넘게 계속 넘치면 **1008** 로 닫고 로그 한 줄 |
| 메시지 크기 | **64 KiB** | 연결을 닫음(1009) |
| 원격 연결 수 | 4 | 받은 뒤 바로 **1013** 으로 닫음, 로그는 초당 한 번 |
| 연결 하나의 보내기 대기열 | 200 (live 제외) | 그 연결을 닫음 |
| send 하나의 시간 | 5 s | 그 연결을 닫음 — 로그 "화면 응답 없음 — 연결을 끊었습니다 (IP · 또는 이 PC 화면)" |
| 무거운 HTTP 조회 | 원격 합쳐서 동시 1 (전체 2) | 바로 429 (위 'HTTP') |

- **로컬(이 PC 화면)에는 속도 한도가 없습니다** — 중단·알람 명령이 버려지면 안 됩니다.
- **로그 묶음** — 연결 거절(출처 · Host) · 원격 연결 수 초과 · 원격 접속 로그는 **IP 별 초당 한 줄**, 묶여 빠진 건수는 다음 줄 끝에 `— 같은 일 N건 더`. 계속 열고 닫는 연결로 로그를 부풀리지 못하게.
- **WebSocket 압축(permessage-deflate)을 끕니다**(`uvicorn ws_per_message_deflate=False`) — 같은 PC · LAN 화면이라 필요 없고, 작게 압축된 프레임이 서버에서 큰 메시지로 풀려 원격 폭주의 비용을 키웁니다.
- 크기 64 KiB 는 가장 큰 올바른 레시피 저장 명령(스텝 100 · 블록 10 · 그룹 5 · 모든 글자 최대 · 한글,
  이 장비 약 26.4 KiB — `tests/test_v047.py` 가 계산)의 약 2배입니다. 그래서 레시피 글자 길이에도 한도가
  있습니다 — 레시피 이름 80(저장 규칙과 같음) · 메모 500 · 블록 이름 · 스텝 이름 40. 화면 입력 칸의
  `maxlength` 도 같은 값입니다.

- 인터락 · 시작 조건 · RF/O3 상태: 색 칩 대신 이름 + 작은 상태 점 목록(2~3 열). 문제인 항목만 노랑 · 빨강 점과 글자,

  평소처럼 바뀝니다. 띠 사각형은 기기 화소에 맞춰 그립니다(125~150 % 배율에서 진하기가 흔들리던 것). 트렌드 탭이 아니면 그리지 않습니다. 캔버스 크기는 바뀔 때만 바꾸고 해상도는 실제 보이는 화소(기기 배율 × CSS zoom)
- **실시간 저장** — 최근 2 분은 받은 그대로, 그보다 오래된 것은 1 s 묶음(최소 · 최대 · 평균), 1 시간보다 오래된 것은
  앞에서 한 번에 자릅니다(5 Hz × 1 h 를 그대로 들던 것 — 계열당 18,000 점). '1시간' 보기의 압력은 fast(최근 10 분)보다
  오래된 쪽을 slow(1 Hz) 압력으로 채웁니다

- 라벨 · 값은 플롯 오른쪽 **라벨 띠**에만 씁니다. 지시선은 플롯 오른쪽 경계에서 **그 선의 마지막 값
  높이**에서 시작해 띠 안에서만 꺾습니다 — 선의 마지막 점에서 출발하면, 데이터가 오른쪽 끝보다 먼저
  끝났을 때(이력 구간이 데이터보다 길 때 · PLC 끊김 · 히터 통신 끊김 · 확대) 지시선이 플롯을 비스듬히
  가로질러 데이터처럼 보입니다. 선의 끝은 플롯 안에 작은 점으로만 표시합니다
- 선이 오른쪽 끝보다 먼저 끝났으면 띠의 값을 흐리게 하고 그 값의 시각(예 `11:50`)을 붙입니다.
  실시간에서 PLC 가 끊기면 띠 값은 `—`
- 라벨은 **절대 겹치지 않습니다** — 줄 간격을 줄이고, 그래도 넘치면 값이 같은 줄을 한 줄로
  묶고(`CH1–CH12 현재 25.0 ℃`), 그래도 넘치면 띠 안에서만 휠로 스크롤합니다. 긴 이름은 말줄임,
  마우스를 올리면 전체 이름. 띠 값에는 단위를 붙입니다. ★ 현재 = 설정이라 묶이면 무엇이 묶였는지 남깁니다
  (`CH1 현재 · 설정`, 예전 `CH1 · CH1`). 긴 묶음은 채널 목록만 `CH4 외 5` 처럼 줄이고 '현재 · 설정' 은 남깁니다
- 마우스를 올리면 플롯 안에는 세로 십자선만, 커서 시각의 값은 띠의 값 자리에, 커서 시각(과 블록·
  스텝 이름)은 x 축 아래(플롯 밖)에 보입니다. ★ 지시선은 hover 때도 그 선의 오른쪽 끝 값 높이에서 시작합니다
  (커서 값 높이에서 시작하면 선이 없는 곳을 가리켰다) — 커서 값은 띠의 글자로만
- 한 그래프 안에서 보이는 선끼리 색이 겹치지 않습니다(12 색). 설정값(설정 ℃ · 설정 sccm 등)은 그
  현재값과 같은 색의 **점선** — 체크박스 색 표시도 같은 규칙입니다
- 창 배율(`core.fit` 의 zoom)을 거친 마우스 좌표는 `getBoundingClientRect` 와 `clientWidth` 의 비로
  고칩니다(십자선 · 끌어서 확대 구간이 커서와 맞게)

### ★ 창 · 끊김 · 입력 보존

- 창 쌓임 순서: **알람 창 > 확인 창 > 나머지 창**(수동 조작 · PIN · 설정 · 시뮬레이터). 확인 창이
  닫힐 때(취소 · Esc · 다른 경로) 확인 콜백을 지우고, 떠 있는 동안 온 확인 요청은 새로 띄우지 않습니다
- ★ **창 키보드** — 창이 열려 있으면 뒤(본 화면 · 아래 창)는 `inert` 로 마우스 · Tab 이 닿지 않고, Tab 은 맨 위 창 안에서만 돕니다. 창이 뜬 직후 0.5 s 와 키를 누르고 있는 동안(자동 반복)은 Enter · Space 를 무시합니다(치던 키가 창 단추를 누르지 않게). 알람 창은 단추가 아니라 **창 자체**에 포커스를 둡니다
- 모든 창에서 Esc 는 닫기(확인 창은 취소). 창이 열리면 포커스가 창 안으로(위험한 동작의 확인 창은
  '취소' 에), 닫히면 원래 자리로. 밸브 칸 · 스위치 · 레시피 체크 칸 · 목록 항목은 Tab 으로 가고
  Enter/Space 로 누릅니다. 이름 입력 창은 Enter 로 확인

  '닫기' 만) · 수동 창 잠금 해제/히터 전원 스위치(공정 중에도) · 시뮬레이터 결함 스위치 ·
  폴더 열기 단추를 화면에서 잠급니다(서버도 거절합니다)
